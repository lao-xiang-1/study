# 计算机网络概述

## 1. 什么是计算机网络

**定义**：将地理位置不同、具有独立功能的多台计算机（端系统）通过通信设备与线路连接起来，由功能完善的网络软件（即协议）实现**资源共享**和**信息传递**的系统。

组成要素：

- **端系统（End System / Host）**：主机，如 PC、手机、服务器。
- **通信链路（Link）**：光纤、双绞线、无线电等物理通道。
- **交换设备（Switch / Router）**：分组交换机，负责转发。
- **协议（Protocol）**：通信双方必须共同遵守的规则。

> 网络的本质可以概括为两点：**协议** 与 **分层**。

## 2. 网络的分类

### 2.1 按覆盖范围

| 类型 | 全称 | 覆盖范围 | 典型例子 |
| :--- | :--- | :--- | :--- |
| PAN | Personal Area Network | 约 10 m | 蓝牙、NFC |
| LAN | Local Area Network | 一栋楼 / 一个校园 | 以太网、Wi-Fi |
| MAN | Metropolitan Area Network | 一座城市 | 城域骨干网 |
| WAN | Wide Area Network | 国家 / 全球 | Internet 主干 |

### 2.2 按交换方式

- **电路交换（Circuit Switching）**：先建立连接（占用信道）→ 通话 → 释放连接。
  - 优点：时延小、实时性好。
  - 缺点：独占资源，线路利用率低。
- **报文交换（Message Switching）**：以整个报文为单位"存储转发"。
  - 缺点：报文长，对节点缓存要求高，转发时延大。
- **分组交换（Packet Switching）**：把报文切分为等长小**分组（Packet）**，逐跳存储转发。
  - 优点：**统计复用**，线路利用率高、灵活、抗故障。
  - 缺点：存在排队时延，需额外首部开销。

> Internet 采用的是**分组交换**。

### 2.3 按拓扑结构

- **总线型**：共享一条总线，冲突多。
- **星型**：所有节点连到中心设备（交换机），便于管理。
- **环型**：首尾相连，令牌环 / 令牌总线。
- **树型**：星型的级联，常用于分层组网。
- **网状（Mesh）**：冗余路径多，可靠性最高，成本也最高。

## 3. 互联网的组成：边缘部分与核心部分

从工作方式看，互联网可划分为**边缘部分**与**核心部分**。

### 3.1 边缘部分

由所有连接在互联网上的**主机（端系统）**组成，是用户**直接使用**的部分。边缘部分利用核心部分提供的服务，使众多主机之间能够互相通信。

边缘部分中主机间的通信，实质上是**进程之间**的通信，主要有两种方式：

- **客户/服务器方式（C/S, Client/Server）**
  - **客户（Client）**是服务请求方，**服务器（Server）**是服务提供方。
  - 客户必须知道服务器的地址，**主动**发起通信；服务器**被动**等待，可同时处理多个客户的请求。
  - 特点：集中管理、易于维护，但服务器易成为**性能瓶颈**和**单点故障**。
- **对等连接方式（P2P, Peer-to-Peer）**
  - 不区分客户与服务器，每台主机**既是请求方又是提供方**，彼此**直接**通信。
  - 特点：去中心化、可扩展性好、健壮；但难以管理，安全与版权问题突出。

> C/S 是"一对多"的集中模式，P2P 是"多对多"的平等模式；二者常在同一应用中混合使用（如 BT 下载）。

### 3.2 核心部分

由大量**网络**以及连接这些网络的**路由器（Router）**组成，是互联网中最复杂的部分，为边缘部分提供**连通性**与**交换**服务。

- 核心部分的关键设备是**路由器**，采用**分组交换（Packet Switching）**。
- 路由器收到分组后，先**存储**（缓存）再查表**转发**到下一跳，即**存储转发**。
- 核心部分不关心分组承载的是何种应用数据，只负责**尽力而为（Best Effort）**地转发。

> 边缘部分是"资源"，用户直接使用；核心部分是"通路"，为边缘提供服务。

## 4. 互联网是"网络的网络"：ISP 与 IXP

**互联网（Internet）**并非单一网络，而是由众多 **ISP** 相互连接而成的"**网络的网络**"。

### 4.1 ISP（互联网服务提供商）

**ISP（Internet Service Provider）**：拥有从互联网管理机构申请到的成块 **IP 地址**，并具备通信线路、路由器等设备，向用户提供互联网接入服务并收取费用。

按覆盖范围可分为**多层次结构**：

| 层次 | 名称 | 覆盖范围 | 特点 |
| :--- | :--- | :--- | :--- |
| 第一层 | 主干 ISP（Tier-1） | 国家 / 全球 | 拥有高速主干网，彼此**对等互联**，不向上游付费 |
| 第二层 | 区域 / 国家 ISP | 一个区域或国家 | 向第一层 ISP 付费购买**中转（Transit）** |
| 第三层 | 本地 / 接入 ISP | 城市 / 校园 / 小区 | 直接面向最终用户，如校园网、企业网 |
| — | 内容提供商（ICP） | 全球 | 如 Google、Netflix，自建数据中心直连骨干，绕过部分层次 |

> ISP 之间是"**客户—提供商**"的商业关系：下层向上层付费购买中转，同级之间可对等互联以免除费用。

### 4.2 IXP（互联网交换点）

**IXP（Internet eXchange Point）**：多个 ISP 在**同一物理地点**（通常是数据中心）互联，实现**对等互联（Peering）**，彼此直接交换流量而**互不收费**。

- **作用**：
  - 减少对上游 ISP 的依赖，降低接入费用。
  - 缩短转发路径，降低时延。
  - 提高冗余与可靠性。
- **与 IXP 相对**的是**专用对等连接（Private Peering）**：两家 ISP 直接铺设光纤互联。

> IXP 是 ISP 之间低成本交换流量的"**集市**"；国家级 IXP 常是本地流量不出境的关键设施。

## 5. 性能指标

### 5.1 性能指标

- **速率（数据率 / 比特率）**：单位 bit/s（bps），注意是**比特**而非字节。
- **带宽（Bandwidth）**：链路所能达到的**最高数据率**，单位 bit/s。
- **吞吐量（Throughput）**：单位时间内实际通过的数据量，受瓶颈链路限制。
- **时延（Delay / Latency）**：

$$\text{总时延} = \text{发送时延} + \text{传播时延} + \text{处理时延} + \text{排队时延}$$

- **发送时延**（传输时延）$=\dfrac{\text{数据长度(bit)}}{\text{发送速率(bit/s)}}$
- **传播时延** $=\dfrac{\text{信道长度(m)}}{\text{电磁波传播速率(m/s)}}$

> 注意区分：发送时延取决于**带宽**与**数据量**，传播时延取决于**距离**与**介质**，二者互不相关。

- **时延带宽积** $=\text{传播时延}\times\text{带宽}$，表示"以比特为单位的链路长度"（管道中能容纳的比特数）。
- **往返时间（RTT, Round-Trip Time）**：从发送方发出到收到对方确认所经历的时间。
- **利用率**：信道利用率与网络利用率，利用率过高会使时延急剧上升。
- **丢包率**：分组丢失的比例，反映网络拥塞程度。
- **时延抖动（Jitter）**：时延的变化量，对实时音视频等应用影响很大。

### 5.2 非性能指标（评估标准）

除上述定量指标外，评价一个网络还需考虑以下**非性能特征**：

| 指标 | 含义 |
| :--- | :--- |
| 费用（Cost） | 建网与运行维护的成本，即性价比 |
| 质量（Quality） | 通信质量，如误码率、抖动 |
| 可靠性（Reliability） | 长期稳定运行与故障恢复的能力 |
| 可扩展性（Scalability） | 便于增加新用户、扩大网络规模 |
| 可管理性（Manageability） | 便于监控、配置与维护 |
| 安全性（Security） | 抵御攻击、保护隐私与数据的能力 |

> 性能指标回答"网络有多快"，非性能指标回答"网络好不好用、值不值得用"。

## 6. 互联网的标准化工作

### 6.1 标准化组织

- **ISOC（Internet Society，互联网协会）**：1992 年成立，负责互联网的全面管理与标准制定工作的领导。
- **IAB（Internet Architecture Board，互联网体系结构委员会）**：ISOC 下设的技术组织，负责协调与把关。
  - **IETF（Internet Engineering Task Force，互联网工程任务组）**：面向**短期 / 中期**的工程问题，制定具体协议标准（如 IP、TCP、HTTP）。
  - **IRTF（Internet Research Task Force，互联网研究任务组）**：面向**长期**研究，如新体系结构、新算法。
- **ITU-T（国际电信联盟电信标准化部门）**：制定电信标准，如 xDSL、光纤传输。
- **ISO（国际标准化组织）**：制定 OSI 参考模型等。

### 6.2 标准的形成过程

互联网标准以 **RFC（Request For Comments，请求评论）** 文档形式发布，编号唯一（如 RFC 791 即 IP 协议）。

1. **互联网草案（Internet-Draft）**：个人或工作组提交，有效期约 6 个月，可随时修改或撤销。
2. **建议标准（Proposed Standard）**：经 IESG 审议通过，进入 RFC 系列，一般要求至少有两个独立实现可互操作。
3. **互联网标准（Internet Standard，STD）**：经长期实践检验、成熟稳定后授予。

- **标准分类**：**法定标准（de jure）** 由权威机构制定（如 OSI）；**事实标准（de facto）** 由市场选择形成（如 TCP/IP）。

> 并非所有 RFC 都是标准：RFC 还包含信息性（Informational）、实验性（Experimental）、历史性（Historic）等文档；文档一旦发布**内容不再修改**，需要修改时必须发布新 RFC 并**废弃（Obsolete）**旧的。

## 7. 体系结构：分层

**为什么要分层**：把复杂问题分解为若干相对独立的子问题，各层只关注自身功能，向上提供服务、向下使用服务，便于实现与演进。

### 7.1 OSI 七层 / TCP-IP 四层 / 教学用五层

| OSI 七层 | TCP/IP 四层 | 五层模型 | 主要功能 |
| :--- | :--- | :--- | :--- |
| 应用层 | 应用层 | 应用层 | 为应用进程提供网络服务 |
| 表示层 | 应用层 | 应用层 | 数据格式转换、加密、压缩 |
| 会话层 | 应用层 | 应用层 | 建立、管理、终止会话 |
| 传输层 | 传输层 | 传输层 | 端到端进程间通信 |
| 网络层 | 网际层 | 网络层 | 分组的路由与转发 |
| 数据链路层 | 网络接口层 | 数据链路层 | 相邻节点间的帧传输 |
| 物理层 | 网络接口层 | 物理层 | 比特流的透明传输 |

> OSI 是**法定标准**（理论参考），TCP/IP 是**事实标准**（工程实用）。

### 7.2 各层典型协议与 PDU

| 层次 | 典型协议 | 数据单元（PDU） |
| :--- | :--- | :--- |
| 应用层 | HTTP、DNS、SMTP、FTP、DHCP | 报文（Message） |
| 传输层 | TCP、UDP | 报文段（Segment）/ 用户数据报（Datagram） |
| 网络层 | IP、ICMP、ARP、OSPF、BGP | 分组 / 数据报（Packet / Datagram） |
| 数据链路层 | 以太网、PPP、HDLC | 帧（Frame） |
| 物理层 | RJ45、光纤、无线 | 比特（Bit） |

> **ARP** 介于网络层与链路层之间，**ICMP** 属于网络层协议。

## 8. 封装与解封装

发送方自上而下逐层添加首部（**封装 / Encapsulation**），接收方自下而上逐层剥离首部（**解封装 / Decapsulation**）。

$$\text{报文} \to \text{报文段} \to \text{分组} \to \text{帧} \to \text{比特流}$$

- 每层只处理本层首部，**不关心上层数据的具体内容**。
- 首部中携带本层所需的控制信息（地址、序号、校验等）。
