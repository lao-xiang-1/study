# OSI 七层体系结构
## 一、为什么要分层

分层的本质是**把复杂的通信问题分解为若干相对独立的子问题**：每一层只解决自己那部分，向上一层**提供服务**，使用下一层提供的服务。好处是各层可独立演进——物理层从双绞线换成光纤，上面的 HTTP 一行都不用改。

## 二、七层总览

| 层 | 英文 | PDU | 核心任务 | 典型协议/设备 |
| :--- | :--- | :--- | :--- | :--- |
| 7 应用层 | Application | 报文 Message | 为应用进程提供网络服务 | HTTP、DNS、SMTP、FTP |
| 6 表示层 | Presentation | 报文 Message | 数据格式转换、加密、压缩 | JPEG、ASCII、TLS 部分功能 |
| 5 会话层 | Session | 报文 Message | 建立/管理/终止会话 | RPC、NetBIOS |
| 4 传输层 | Transport | 报文段 Segment | **端到端**进程间通信 | TCP、UDP |
| 3 网络层 | Network | 分组 Packet | 路由与转发、异构网互联 | IP、ICMP、OSPF；路由器 |
| 2 数据链路层 | Data Link | 帧 Frame | **相邻节点**间的帧传输 | 以太网、PPP；交换机、网桥 |
| 1 物理层 | Physical | 比特 Bit | 比特流的**透明传输** | RJ45、光纤；中继器、集线器 |

## 三、自下而上逐层解释

### 第 1 层 物理层（Physical Layer）

解决「**如何在传输介质上传输比特流**」，不关心比特的含义，只要求**透明传输**（发什么比特，收什么比特）。

- 定义的是接口的四大特性：**机械特性**（接口形状、引脚数）、**电气特性**（电压范围、传输速率）、**功能特性**（某条线的电平含义）、**规程特性**（信号时序）。
- 数据单位是**比特（bit）**，关注的是"1 和 0 用什么电平/光强表示"。
- 设备：**中继器（Repeater）**、**集线器（Hub）**——只做信号放大与整形，不识别帧。

### 第 2 层 数据链路层（Data Link Layer）

在**相邻的两个节点**之间传输以**帧（Frame）**为单位的数据。三个典型功能：

- **成帧（Framing）**：把比特流切分成帧，用首部/尾部标记边界。
- **差错控制**：CRC 校验，检出错误则丢弃（或重传）。
- **流量控制与介质访问控制（MAC）**：控制发送方速率，解决共享信道的争用（如 CSMA/CD）。
- 地址是 **MAC 地址**（物理地址/硬件地址），只在**同一局域网内**有意义。
- 设备：**网桥（Bridge）**、**交换机（Switch）**——能识别帧和 MAC 地址，按地址转发。

> 注意：链路层管的是"**一跳**"，不管跨了多少个网络。

### 第 3 层 网络层（Network Layer）

解决「**分组如何从源主机穿越多个网络到达目的主机**」，即**路由与转发**。

- 核心是**路由选择（Routing）**（决定走哪条路，由路由协议算出来）和**分组转发（Forwarding）**（按转发表把分组扔给下一跳）。
- 地址是 **IP 地址**，**全局唯一、跨越所有网络**——这正是它和 MAC 地址的根本区别。
- 屏蔽下层异构：无论下面是以太网还是 Wi-Fi，IP 层之上看到的都一样。
- 设备：**路由器（Router）**——它连接的是**网络**，不是主机。
- 协议：**IP、ICMP、OSPF、BGP**；**ARP** 严格说介于网络层与链路层之间。

### 第 4 层 传输层（Transport Layer）

承上启下的一层，提供**端到端（End-to-End）**、即**进程到进程**的通信。这是它和第 3 层"主机到主机"的关键区别。

- **复用与分用（Multiplexing/Demultiplexing）**：用**端口号**区分同一台主机上的不同进程。
- **TCP**：面向连接、可靠、有序、有流量控制与拥塞控制 → 报文段（Segment）。
- **UDP**：无连接、尽力而为、开销小 → 用户数据报（Datagram）。
- 传输层是**真正把网络细节隔离掉**的一层：上面写应用的人完全不用管下面用的是 IP 还是别的。

### 第 5 层 会话层（Session Layer）

负责**建立、管理、终止会话**，以及会话的**同步**——在数据流中插入**同步点（Synchronization Point）**，传输中断后可从最近的同步点续传，而不必从头再来。还负责对话控制（谁先说、谁后说）。

> 在真实工程中，这一层几乎没有独立实现，功能大多被应用层协议顺带做掉了——这是 OSI 被诟病"层次过多"的典型例子。

### 第 6 层 表示层（Presentation Layer）

处理数据的**表示形式**，保证不同机器（大端/小端、不同字符集）之间能互相理解：

- **格式转换**：如 EBCDIC ↔ ASCII、大端 ↔ 小端。
- **加密与解密**、**压缩与解压缩**。

### 第 7 层 应用层（Application Layer）

面向**具体应用**的一层，直接为用户进程提供服务，是用户唯一能"看见"的一层：HTTP（Web）、DNS（域名解析）、SMTP/POP3（邮件）、FTP（文件传输）、DHCP（动态配置）。

> OSI 的"应用层"是**最靠近用户的一层**，但它本身并不包含浏览器、邮件客户端这类**程序**——那些程序是通过应用层协议来通信的。

## 四、关键概念

1. **对等层通信（Peer-to-Peer）**：数据在逻辑上是"第 $n$ 层 ↔ 第 $n$ 层"之间传递的，这称为**虚拟通信**；而物理上数据只能沿**垂直方向**逐层穿过，在发送方逐层加首部（**封装**），在接收方逐层剥首部（**解封装**）。所以"第 3 层直接跟对面第 3 层说话"只是一种抽象。

## 五、为什么 OSI 输了给 TCP/IP

| 原因 | 说明 |
| :--- | :--- |
| 层次过多、功能重复 | 会话层、表示层缺乏独立实现，实际被应用层吸收 |
| 过于理想化 | 先定标准后做实现，理论与工程脱节 |
| 时机太晚 | 标准制定拖沓，而 TCP/IP 已随 UNIX 免费流行 |
| 定位差异 | OSI 是**法定标准（de jure）**，TCP/IP 是**事实标准（de facto）** |

> 但 OSI 的**分层思想**本身胜出了——它是理解网络协议最好的教学框架，所以教材普遍仍从七层讲起。

# TCP/IP 体系结构

## 一、由来与地位

**TCP/IP** 并非先有模型再定协议，而是**先有协议、后总结出模型**——它诞生于 1969 年的 **ARPANET**（美国国防部高级研究计划局网络），1974 年 Cerf 与 Kahn 提出 TCP 的雏形，1983 年 1 月 1 日 ARPANET 全面切换到 TCP/IP，从此成为互联网的运行基础。

- 它不是"一个协议"，而是一个**协议族（Protocol Suite）**，因其中最核心的两个协议 **TCP** 与 **IP** 而得名。
- 它由 **IETF** 以 **RFC** 文档形式维护，属于**事实标准（de facto）**——没有任何权威机构强制推行，是市场与工程实践选择的结果。
- 与 OSI 相反：**OSI 是理论先行、标准先定**，TCP/IP 是**实现先行、边用边改**。

> 一句话概括：**OSI 是"先画好图纸再盖楼"，TCP/IP 是"先盖起来住着，再回头画图纸"。** 结果后者活了下来。

## 二、四层结构总览

| 层 | 英文 | PDU | 核心任务 | 典型协议 |
| :--- | :--- | :--- | :--- | :--- |
| 4 应用层 | Application Layer | 报文 Message | 为用户进程提供网络服务 | HTTP、DNS、SMTP、FTP、DHCP |
| 3 传输层 | Transport Layer | 报文段 Segment | **端到端**进程间通信 | TCP、UDP |
| 2 网际层 | Internet Layer | 分组 / 数据报 Packet | 路由与转发、互联异构网络 | **IP**、ICMP、ARP、OSPF、BGP |
| 1 网络接口层 | Network Interface Layer | 帧 Frame | 接入具体物理网络 | 以太网、PPP、Wi-Fi |

与 OSI 的对应关系：

- **网络接口层** ≈ OSI 的 **物理层 + 数据链路层**，TCP/IP 对它**几乎不作规定**，只要求"能把 IP 分组发出去"。
- **网际层** ≈ OSI 的 **网络层**，但**只提供无连接服务**。
- **传输层** ≈ OSI 的 **传输层**，同时提供面向连接与无连接两种服务。
- **应用层** ≈ OSI 的 **会话层 + 表示层 + 应用层**，三层功能合并为一层。

> TCP/IP 的层名在不同教材中叫法不一：网络接口层也称**主机—网络层（Host-to-Network Layer）**，网际层也称**互联网层**。认准功能，不要被名字绕晕。

## 三、自下而上逐层解释

### 第 1 层 网络接口层（Network Interface Layer）

对应 OSI 的下两层，负责**把 IP 分组封装成帧，通过具体的物理网络发送出去**。

- TCP/IP **故意不定义这层的具体协议**——以太网、Wi-Fi、PPP、HDLC 都能跑 IP。这正是 IP 能"统一江湖"的前提：**不挑底层**。
- 地址是 **MAC 地址**，只在本局域网内有效；**ARP** 负责把 IP 地址解析为 MAC 地址，工作在网际层与接口层的边界上。
- 设备：网卡、交换机、集线器、中继器。

### 第 2 层 网际层（Internet Layer）

TCP/IP 的**核心与灵魂**，解决"**分组如何跨越多张网络到达目的主机**"。

- **IP 协议**提供**无连接、不可靠、尽力而为（Best Effort）**的分组交付服务：
  - 不保证送达、不保证顺序、不保证不重复、不保证时延。
  - 分组一旦出错或超时，**由上层（TCP）或端系统负责处理**，网络本身只管转发。
- 地址是 **IP 地址**，**全局唯一、跨越所有网络**，是全网唯一的寻址体系。
- 屏蔽下层异构：无论下面是以太网还是 Wi-Fi，**在 IP 之上看到的都是统一的网络**——这就是"**IP over Everything**"。
- 配套协议：**ICMP**（差错与控制报文，如 `ping`）、**ARP**（地址解析）、**IGMP**（组播）；路由协议 **RIP、OSPF、BGP**。
- 设备：**路由器（Router）**——连接**网络**，只查表转发，不关心分组承载的是什么应用数据。

> 网际层只做两件事：**寻址**与**转发**。它刻意保持简单——**复杂留给端系统**（见第五节）。

### 第 3 层 传输层（Transport Layer）

提供**端到端（End-to-End）**、即**进程到进程**的通信，是 TCP/IP 中承上启下的一层。

- **复用与分用**：用**端口号**区分同一台主机上的不同进程。
- **TCP（传输控制协议）**：面向连接、可靠、有序、有流量控制与拥塞控制 → **报文段（Segment）**。
- **UDP（用户数据报协议）**：无连接、不可靠、开销小、时延低 → **用户数据报（Datagram）**。
- **与 OSI 的关键差异**：OSI 的传输层只提供面向连接的服务，而 TCP/IP 的传输层**两种服务并存**——这正是它务实的地方。

> TCP 的可靠性（确认、重传、排序、窗口）是**在端系统上实现的**，网络核心并不知情——这是"端到端原则"最典型的体现。

### 第 4 层 应用层（Application Layer）

面向**具体应用**，把 OSI 的**会话层、表示层、应用层**三层的功能**全部吸收合并**。

- 会话管理、数据格式转换、加密压缩等，都由具体的应用层协议**各自按需实现**，不再单独分层。
- 典型协议：**HTTP/HTTPS**（Web）、**DNS**（域名解析）、**SMTP/POP3/IMAP**（邮件）、**FTP**（文件传输）、**DHCP**（动态主机配置）、**Telnet/SSH**（远程登录）、**SNMP**（网络管理）。
- 用户唯一能"看见"的一层，浏览器、邮件客户端等**应用程序**都是通过这一层的协议来通信的。

> OSI 把"会话、表示"独立成层，本意是复用；但实践中这两层几乎从无独立实现，反而成了冗余。TCP/IP 直接把它们**还给应用层**——这是四层模型更务实的一个缩影。

## 四、沙漏模型：IP 是细腰

TCP/IP 的层次结构常被画成一个**沙漏（Hourglass）**——**中间细、两头粗**：

```text
        应用层      HTTP   DNS   SMTP   FTP   SSH  ...
                     \     |     |     /    /
        传输层           TCP        UDP
                           \        /
        网际层                IP            ← 细腰（Narrow Waist）
                           /        \
   网络接口层     以太网     Wi-Fi     PPP   光纤 ...
```

- **细腰是 IP**：上面所有应用、所有传输协议，下面所有物理网络，**都必须经过 IP 这一个窄口**。
- 由此得到两句名言：
  - **IP over Everything**——IP 能跑在任何底层网络之上。
  - **Everything over IP**——任何应用都能跑在 IP 之上。
- **好处**：只需替换腰部（IPv4 → IPv6），上下两层都不必大动；**代价**：IP 一旦僵化，整个互联网都跟着僵化（如 IPv4 地址耗尽、NAT 的广泛使用、中间盒 Middlebox 的干扰）。

> 沙漏模型解释了 TCP/IP 为什么能赢：**它把变化留在两端，把不变留在中间**。

## 五、设计哲学

| 原则 | 含义 |
| :--- | :--- |
| **端到端原则**（End-to-End Principle） | 网络核心只负责**尽力转发**，可靠性、有序性、拥塞控制等复杂功能交给**端系统**实现 |
| **尽力而为**（Best Effort） | IP 不保证送达、顺序、不重复、时延，把"可靠性"变成可选项而非必需品 |
| **无状态**（Stateless） | 路由器**不保存连接状态**，每个分组独立转发，因而易于扩展、容错性强 |
| **兼容并蓄** | 不规定底层与上层的具体协议，只规定中间的 IP 与 TCP/UDP |
| **分层但不严格** | 不强调服务、接口、协议的严格界限，允许**跨层调用**（如 ICMP、ARP） |

> **智能在端系统，而不在网络**——这是 TCP/IP 与 OSI（主张网络本身要"聪明"、要保证可靠）最根本的哲学分歧，也是它更适应异构、松散、爆炸式增长的互联网的原因。

## 六、与 OSI 的对比

| 对比项 | OSI 七层 | TCP/IP 四层 |
| :--- | :--- | :--- |
| 层数 | 7 | 4 |
| 制定者 | ISO（国际标准化组织） | IETF（民间工程组织） |
| 标准性质 | **法定标准（de jure）** | **事实标准（de facto）** |
| 出发点 | 先有模型，后有协议 | 先有协议，后总结模型 |
| 网络层服务 | 面向连接 + 无连接 | **只有无连接**（IP） |
| 传输层服务 | 只有面向连接 | **面向连接 + 无连接**（TCP/UDP） |
| 分层严格性 | 严格，服务/接口/协议界限分明 | 不严格，允许跨层 |
| 智能位置 | **网络智能**（网络负责可靠） | **端系统智能**（端到端原则） |
| 上三层 | 会话层、表示层、应用层分立 | 合并为**应用层** |
| 现实地位 | 理论参考、教学框架 | **实际运行**的互联网基础 |

> 两者并非对立：OSI 提供了**概念的完备性**（哪些功能是通信中必须解决的），TCP/IP 提供了**工程的可实现性**。学网络时用 OSI 建立概念，用 TCP/IP 理解现实。

## 七、教学用五层模型

OSI 七层偏理论、TCP/IP 四层偏工程，二者在教学中都不够顺手，因此教材（如谢希仁《计算机网络》）折中出**五层模型**：

| 五层模型 | 来源 | 说明 |
| :--- | :--- | :--- |
| 应用层 | 取 TCP/IP 的应用层 | 合并了 OSI 的会话层、表示层 |
| 传输层 | 取 TCP/IP 的传输层 | 端到端进程间通信 |
| 网络层 | 取 TCP/IP 的网际层 | 路由与转发 |
| 数据链路层 | **拆开** TCP/IP 的网络接口层 | 相邻节点间的帧传输 |
| 物理层 | **拆开** TCP/IP 的网络接口层 | 比特流的透明传输 |

- **上三层合一、下两层拆开**——因为 TCP/IP 的网络接口层把物理与链路混在一起，不利于讲清"帧"与"比特"的区别。
- 记忆口诀：**"应用、传输、网络、链路、物理"**，从上层到下层。

> 实用原则：**讲概念用五层，谈实际协议用四层，读文献见七层**。三套模型只是切法不同，功能没有增减。
