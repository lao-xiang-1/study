# Python 模块（Module）与包（Package）

## 1. 模块与包的基本定义

### 1.1 模块（Module）

**模块是一个包含 Python 代码的文件**，文件名就是模块名加上 `.py` 后缀。

```
mymath.py   ← 这是一个模块
```

- 导入模块时，Python 会执行文件中的顶层代码
- 多次 `import` 同一个模块，只会执行一次（由 `sys.modules` 缓存）
- c扩展的.so文件也是一个模块

### 1.2 包（Package）

**包是一个包含 `__init__.py` 的目录**，用于组织多个模块。

```
mypackage/
├── __init__.py      ← 标识这是一个包
├── module_a.py      ← 包中的模块
└── module_b.py      ← 包中的模块
```

- Python 3.3+ 支持没有 `__init__.py` 的目录作为包的一部分（PEP 420）

---

## 2. 模块的特殊属性

模块被加载后，Python 会自动注入一组**特殊属性（dunder attributes）**：

| 属性 | 说明 | 示例 |
|------|------|------|
| `__name__` | 模块名称；直接运行时值为 `"__main__"` | `mymath` / `__main__` |
| `__file__` | 模块文件的绝对路径 | `/home/user/mymath.py` |
| `__package__` | 模块所属的包名 | `mypackage` / `None` |
| `__path__` | 包的路径列表（仅包有） | `['/home/user/mypackage']` |
| `__all__` | 控制 `from module import *` 的导出列表 | `['foo', 'bar']` |
| `__doc__` | 模块的文档字符串 | `"数学工具模块"` |
| `__loader__` | 加载该模块的加载器对象 | `<_frozen_importlib...>` |
| `__spec__` | 模块的导入规范对象 | `ModuleSpec(...)` |
| `__cached__` | 编译后字节码文件（`.pyc`）的路径 | `.../__pycache__/...` |

### `__name__` 的经典用法

```python
# mymath.py

def add(a, b):
    return a + b

def main():
    print(f"2 + 3 = {add(2, 3)}")

if __name__ == "__main__":
    main()
```

| 运行方式 | `__name__` 的值 |
|----------|----------------|
| `import mymath` | `"mymath"` |
| `python mymath.py` | `"__main__"` |

> `if __name__ == "__main__":` 是区分**被导入**和**直接运行**的标准写法。

## 3. `__init__.py` 的作用

`__init__.py` 是包的核心，有两个作用：

1. **标识目录为 Python 包**（普通包必须有，命名空间包可以没有）
2. **控制包的公共 API** —— 决定 `import package` 或 `from package import *` 时暴露什么

### 典型包结构

```
pcx/
├── __init__.py              # 顶层包入口：聚合核心 API
├── core/
│   ├── __init__.py          # 聚合 core 子包的公共 API
│   ├── _module.py           # 内部实现（_前缀）
│   └── _parameter.py
├── nn/
│   ├── __init__.py
│   └── _layer.py
└── utils/
    ├── __init__.py
    └── _misc.py
```

### `__init__.py` 中的常见操作

```python
# pcx/core/__init__.py

# 1. 从子模块显式导入，暴露给包命名空间
from ._module import BaseModule, Module
from ._parameter import BaseParam, Param, ParamDict

# 2. 定义 __all__，控制通配符导入
__all__ = [
    "BaseModule",
    "Module",
    "BaseParam",
    "Param",
    "ParamDict",
]

# 3. 初始化包级状态（较少见）
_package_version = "1.0.0"
```

## 4. `__all__` —— 控制公共 API

`__all__` 是一个**模块级列表**，精确控制 `from module import *` 会导入哪些名称。

### 基本用法

```python
# mymodule.py

__all__ = ["public_func", "PublicClass"]

def public_func():
    pass

class PublicClass:
    pass

def _private_func():   # 下划线开头，默认不被 import * 导入
    pass
```

```python
from mymodule import *

public_func()       # ✓ 可用
PublicClass()       # ✓ 可用
_private_func()     # ✗ NameError
```

### 注意点

- **没有 `__all__`**：`from X import *` 会导入所有不以 `_` 开头的名称
- **`__all__` 在 `__init__.py` 中**：控制包的公共接口
- **`__all__` 在普通模块中**：控制该模块的公共接口
- `__all__` 不影响**显式导入**：`from mymodule import _private_func` 仍然可以

## 5. 导入方式详解

### 5.1 绝对导入

从项目的顶级包开始，完整写出路径：

```python
import pcx.core._parameter
from pcx.core import Param
from pcx.core._parameter import ParamDict
```

**推荐**：代码可读性高，路径清晰，不易歧义。

### 5.2 相对导入

以当前模块为基准，使用点号：

```python
# pcx/predictive_coding/_vode.py

from ..core._random import RKG, RandomKeyGenerator      # 上一级
from ..core._parameter import Param                      # 上一级
from ._energy import zero_energy                         # 同级
```

| 语法 | 含义 |
|------|------|
| `from .module import X` | 同级目录 |
| `from ..module import X` | 上一级目录 |
| `from ...module import X` | 上两级目录 |

**限制**：相对导入只能在包内部使用，直接运行包含相对导入的文件会报错：

```
ImportError: attempted relative import with no known parent package
```

## 6. 模块搜索路径

当执行 `import foo` 时，Python 按以下顺序查找：

1. **`sys.modules`** —— 检查是否已缓存
2. **内置模块** —— 如 `sys`、`builtins`
3. **`sys.path`** —— 按顺序搜索路径列表

### `sys.path` 的组成

```bash
atri_suki@xianghy:~$ python3 -c "import sys;print(sys.path)"
['', '/usr/lib/python312.zip', '/usr/lib/python3.12', '/usr/lib/python3.12/lib-dynload', '/usr/local/lib/python3.12/dist-packages', '/usr/lib/python3/dist-packages']
```

> 第一个空字符串相当于当前工作目录（执行python程序的路径）

### 常用技巧

```python
# 临时添加搜索路径
import sys
sys.path.insert(0, '/path/to/my/package')

# 推荐：使用 PYTHONPATH 环境变量
# export PYTHONPATH=/path/to/my/package:$PYTHONPATH
```

## 7. 导入机制原理

### 7.1 首次导入的流程

```
import mymodule
    │
    ▼ ① 查找（Find）
    在 sys.path 中找到 mymodule.py
    │
    ▼ ② 加载（Load）
    创建模块对象，执行文件中的顶层代码
    │
    ▼ ③ 缓存（Cache）
    将模块存入 sys.modules['mymodule']
    │
    ▼ ④ 绑定（Bind）
    在当前命名空间中创建名称 mymodule
```

### 7.2 重复导入

```python
import mymodule   # 首次：执行文件
import mymodule   # 第二次：直接从 sys.modules 取缓存，不重新执行
```

如果需要强制重新加载：

```python
import importlib
import mymodule
importlib.reload(mymodule)   # 重新执行模块代码
```

## 8. 命名规范与最佳实践

| 约定 | 示例 | 含义 |
|------|------|------|
| 无下划线 | `utils.py` | 公共模块 |
| 单下划线前缀 | `_utils.py` | 内部实现，不建议外部直接导入 |
| 双下划线前缀 | `__init__.py` | 特殊模块（包入口等） |

## 9. 常见问题

### Q1: 循环导入怎么办？

**A → B → A** 的循环导入会导致问题。解决方法：

1. **重构**：提取公共部分到第三个模块
2. **延迟导入**：在函数内部 import
3. **调整导入顺序**：确保底层模块先导入

```python
# 方法2：延迟导入
# module_a.py
def some_func():
    from . import module_b   # 在函数内部导入，避免顶层循环
    module_b.do_something()
```
