## 1. 内置函数（一）：类型检查与反射

### 1.1 `isinstance(obj, type)` —— 类型检查

**这是 PCX 中使用频率最高的内置函数**，主要用于 pytree 遍历时的叶子节点识别。

```python
# pcx/core/_tree.py:168 —— 判断是否是参数，决定是否展开为叶子
jtu.tree_map(_map_fn, pydag, *rest, is_leaf=lambda x: isinstance(x, BaseParam))

# pcx/core/_module.py:171 —— 找到所有 Module 子节点
tree_apply(
    lambda m: m._mode.set(value),
    lambda x: isinstance(x, Module),   # 只有 Module 类型才设置 mode
    self
)

# pcx/predictive_coding/_vode.py:267-268 —— 区分 Param 属性和 cache 键
if hasattr(self, _target) and isinstance(
    (_param := getattr(self, _target)), Param
):
    _param.set(_value)        # 是注册的 Param → 直接设置
else:
    self.cache[_target] = _value  # 不是 → 存入缓存
```

**关键用法**：`isinstance(obj, SomeClass)` —— 检查 `obj` 是否是 `SomeClass` 或其子类的实例。这支持继承链，例如 `isinstance(vode_param, BaseParam)` 返回 `True`。

**`is_leaf` 模式**：JAX 的 `tree_map` / `tree_flatten` / `tree_leaves` 接受 `is_leaf` 参数。当 `is_leaf(x)` 返回 `True` 时，该节点被视为叶子不再展开。PCX 大量使用 `is_leaf=lambda x: isinstance(x, BaseParam)` 来让参数成为叶节点。

### 1.2 `hasattr(obj, name)` —— 属性存在检查

```python
# pcx/core/_module.py:184 —— 检查 equinox 模块是否有 inference 属性
tree_apply(
    lambda eqx_m: eqx_m.inference.set(False),
    lambda x: hasattr(x, "inference"),   # 不是所有层都有 inference
    self, False,
)

# pcx/predictive_coding/_vode.py:267 —— 检查 Vode 是否有某个属性
if hasattr(self, _target) and isinstance(...):
```

### 1.3 `getattr(obj, name)` —— 动态属性访问

```python
# pcx/predictive_coding/_vode.py:268 —— 按字符串名动态获取属性
(_param := getattr(self, _target))   # 如果 _target = "h"，等价于 self.h

# pcx/core/_static.py:90 —— 代理模式的核心
def __getattr__(self, __name: str) -> Any:
    return getattr(self._static_value, __name)
```

**与 `. ` 点号访问的区别**：`getattr(obj, "attr_name")` 允许属性名是**运行时变量**，这是 `Ruleset` 能够动态读写 Vode 任意属性的基础。

### 1.4 `id(obj)` —— 对象唯一标识

```python
# pcx/core/_tree.py:259 —— 检测重复引用（PyDAG → PyTree 转换）
elif isinstance(x, BaseParam) and ((_ref := _seen(id(x))) is not None):
    return _BaseParamRef(_ref)
```

`id()` 返回对象的内存地址，在 CPython 中是一个整数。PCX 用 `id(x)` 作为缓存的 key 来检测**同一个对象的多次引用**。这是将 PyDAG（有共享节点）转换为 PyTree（无共享节点）的关键。

## 2. 内置函数（二）：`filter` / `map` / `zip` —— 函数式迭代

### 2.1 `filter(fn, iterable)` —— 惰性过滤

>对 `iterable` 中的每个元素调用 `fn(element)`，保留那些返回**真值**的元素。
>如果 `fn` 为 `None`，则返回 `iterable` 中不为 0（假值）的元素

```python
# pcx/core/_module.py:135-137 —— 筛选指定类型的子模块
yield from filter(
    lambda x: isinstance(x, cls),
    jtu.tree_leaves(_leaves, is_leaf=lambda x: isinstance(x, cls)),
)
```

**关键特性**：`filter` 返回的是**迭代器**（惰性求值），不是列表。结合 `yield from` 可以不构建任何中间列表就把过滤结果逐项输出。

```python
# pcx/core/_tree.py:203 —— 筛选所有匹配的参数
values = filter(
    filter_fn,
    jtu.tree_leaves(params, is_leaf=lambda x: isinstance(x, BaseParam)),
)
```

### 2.2 `map(fn, iterable)`

```python
# pcx/core/_module.py:78-79 —— 将属性名转为 JAX 的 GetAttrKey
tuple(
    zip(
        map(lambda k: jtu.GetAttrKey(k), module.__dict__.keys()),
        #  ^^^ 将每个 str 键映射为 GetAttrKey 对象
        module.__dict__.values(),
    )
)

# pcx/core/_parameter.py:122 —— 格式化输出
f"[{','.join(map(str, self.shape))}], {self.dtype}"
#                  ^^^^^^^^ 将每个维度转为字符串，然后用逗号连接
```

>`map(str, seq)` 等价于 `(str(x) for x in seq)`，但作为函数参数传递时更紧凑。

### 2.3 `zip(*iterables)` —— 并行迭代

#### 基本用法
```python
names = ["Alice", "Bob", "Charlie"]
ages = [25, 30, 35]

# 按位置配对
zipped = zip(names, ages)
print(list(zipped))
# [('Alice', 25), ('Bob', 30), ('Charlie', 35)]
```

**注意点：**
- `zip` 返回的是迭代器，不是列表
- 如果传入的列表长度不等，以最短的输入为准，多余元素被忽略（Python 3.10+ 可加 `strict=True`，长度不等时报错）

#### pcx示例
```python

    zip(
        map(lambda k: jtu.GetAttrKey(k), module.__dict__.keys()),
        module.__dict__.values(),
    )
)
# 结果：((GetAttrKey("h"), h_value), (GetAttrKey("cache"), cache_value), ...)

# pcx/core/_module.py:92 —— 重建 __dict__
_module.__dict__ = dict(zip(aux_data, children))
#                      ^^^ 将 (键元组, 值元组) 变成有序的键值对迭代器
```

## 3. 内置函数（三）：`iter` / `next` / `len` / `tuple` / `dict` —— 容器操作

### 3.1 `iter(obj)` —— 获取迭代器

#### 简要示例
```python
names = ["Alice", "Bob", "Charlie"]
ids = [101, 102, 103, 104]  # 多了一个

# 创建迭代器，逐个分配
it = iter(ids)

for name in names:
    print(f"{name} -> {next(it)}")

# 检查是否恰好用完
try:
    extra = next(it)
    print(f"❌ 多余: {extra}")
except StopIteration:
    print("✅ 数量刚好")
```
**输出**：
```
Alice -> 101
Bob -> 102
Charlie -> 103
❌ 多余: 104
```

#### pcx示例
```python
# pcx/core/_tree.py:211 —— 用迭代器逐个消费值序列
_values_it = iter(values)            # 从序列创建迭代器
inject_fn(x, next(_values_it).get()) # 逐个消费

# 验证没有多余的值（严格模式检查）
try:
    next(_values_it)                 # 如果还能取到下一个，说明值太多了
    raise ValueError("...")
except StopIteration:
    pass                             # 正常：所有值都被消费了
```

**`iter` + `next` + `StopIteration` 模式**：Python 中迭代器在耗尽时抛出 `StopIteration`。这段代码利用这个特性来验证"值的数量必须恰好等于叶子的数量"。

### 3.2 `tuple(iterable)` —— 强制求值

```python
# pcx/predictive_coding/_vode.py:259 —— 将生成器结果具体化
rules = tuple(self.ruleset.filter(self.status, _rule_pattern))
#       ^^^^^ 生成器 → 元组：催动生成器立即执行，结果可以多次遍历

# pcx/core/_tree.py:170
return tuple(_values)


# pcx/core/_module.py:70
return tuple(module.__dict__.values()), tuple(module.__dict__.keys())
```

**为什么需要 `tuple()`？** 生成器是惰性的，只在迭代时求值。`tuple()` 强制立即求值并将结果保存为元组。如果不做这一步，后续的 `len(rules)` 会在迭代中消耗掉生成器，导致 `for` 循环拿不到数据。

### 3.3 `dict(obj)` —— 构建字典

```python
# pcx/core/_module.py:92
_module.__dict__ = dict(zip(aux_data, children))
```

`dict(zip(keys, values))` 是 Python 中最紧凑的"用两个列表构建字典"的方式。

## 6. 内置函数（六）：`any` / `all` —— 逻辑聚合

```python
scores = [55, 72, 88, 40, 90]

# 是否有及格（>=60）的？
any(s >= 60 for s in scores)   # True

# 是否全部及格？
all(s >= 60 for s in scores)   # False（因为 55 和 40 不及格）
```

`any`/`all` 都**短路求值**——`any` 遇到第一个 `True` 就停止，`all` 遇到第一个 `False` 就停止。

### 7.2 `yield` / `yield from` —— 生成器

```python
# pcx/core/_module.py:135 —— yield from：委托给子生成器
def submodules(self, *, cls=None):
    cls = cls or BaseModule
    _leaves, _ = eqx.tree_flatten_one_level(self)

    yield from filter(         # ← 将 filter 迭代器的每一项逐项产出
        lambda x: isinstance(x, cls),
        jtu.tree_leaves(_leaves, is_leaf=lambda x: isinstance(x, cls)),
    )

# pcx/predictive_coding/_vode.py:98 —— yield：逐项产出匹配的规则
def filter(self, status, rule_pattern):
    for _pattern, _rules in self.rules.items():
        if re.match(_pattern, status) is None:
            continue
        for _rule in _rules:
            if _match := re.match(rule_pattern, _rule):
                yield _match.group(1, 2)   # 惰性产出
```

**`yield from` 的本质**：
```python
# 这两个等价：
yield from iterable

# 等价于：
for item in iterable:
    yield item
```

但 `yield from` 更高效（直接委托给底层迭代器，不经过 Python 层的 for 循环）。

### 7.3 `yield` 在上下文管理器中的特殊用法

```python
import contextlib, time

@contextlib.contextmanager
def timed(label):
    # === with 进入时执行 ===
    print(f"[{label}] 开始...")
    t0 = time.time()

    yield                           # ← 暂停！执行 with 块内的用户代码

    # === with 退出时执行（清理） ===
    t1 = time.time()
    print(f"[{label}] 结束，耗时 {(t1 - t0) * 1000:.1f} ms")


# 使用
with timed("数据加载"):
    process_data()      # ← 这行代码执行时，yield 让出控制权
```

**执行顺序图解：**

```
with timed("xxx"):
    ↓
    print("开始...")      ← yield 之前的代码（进入时）
    t0 = time.time()
    ↓
    yield ────────────── → 暂停，转去执行 with 块内的代码
                              ↓
                              process_data()
                              ↓
    ← ─────────────────── 块内代码结束，回到 yield 之后
    ↓
    print("结束...")      ← yield 之后的代码（退出时）
    计算耗时
```

`yield` 将函数分成"进入"和"退出"两部分。`yield` 之前的代码在 `with` 进入时执行，`yield` 之后的代码在 `with` 退出时执行。

### 7.6 `:=` (walrus operator) —— 赋值表达式

Python 3.8 引入。在表达式内部边赋值边使用，避免先赋值再判断的两行写法。

```python
# 传统写法：两行
n = cache(x)
if n is not None:
    ...

# 海象运算符：一行，n 的作用域被限制在 if 块内
if (n := cache(x)) is not None:
    ...
```

**注意**：`:=` 必须用括号包裹 `(n := val)` 才能再跟 `is`/`is not`/`==` 做比较，否则优先级会出错。

## 8. 标准库（一）：`functools`

### 8.1 `functools.partial(func, *args, **kwargs)` —— 固定参数

**PCX 中 `partial` 的核心用途是解决 JAX 注册的签名不匹配问题。**

```python
# pcx/core/_module.py:61-63 —— 元类注册 pytree
jax.tree_util.register_pytree_with_keys(
    _cls,
    ...
    unflatten_func=functools.partial(
        _BaseModuleMeta.unflatten_module, cls=_cls
        #  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  原始函数
        #                                    ^^^^^^^^ 固定的关键字参数
    ),
)

# unflatten_module 的签名：
# def unflatten_module(aux_data, children, *, cls) -> "BaseModule":
#     ...

# JAX 调用的是: unflatten_func(aux_data, children)
# 而不是:       unflatten_func(aux_data, children, cls=xxx)

# partial 解决了这个矛盾：cls 被预先绑定，剩余签名恰好匹配 JAX 的调用约定
```

**`partial` 的原理（简化版）**：
```python
def partial(func, *more_args, **more_kwargs):
    def wrapper(*args, **kwargs): # 返回的wrapper只接受func的部分参数
        return func(*args, *more_args, **kwargs, **more_kwargs) # 实际调用的fun传入了更多参数（事先传入partial）
    return wrapper
```

### 8.2 `functools.reduce(fn, iterable)` —— 累积计算

```python
# pcx/predictive_coding/_energy_module.py:45-46 —— 递归能量求和
def energy(self) -> jax.Array:
    return functools.reduce(
        lambda x, y: x + y,                              # 二元操作：加法
        (m.energy() for m in self.submodules(cls=EnergyModule))
        # ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
        # 生成器：每个子模块的能量值
    )
```

**`reduce` 的展开等价写法**：

```python
# reduce(lambda x, y: x + y, (a, b, c, d))
# 等价于:
# (((a + b) + c) + d)
```

这里用 `reduce` 替代了 `sum()`，因为返回值是 JAX 数组而非 Python 数字。

### 10.3 `@contextlib.contextmanager` —— 生成器式上下文管理器

```python
# pcx/utils/_misc.py:16-70
@contextlib.contextmanager
def step(module, status=None, *, clear_params=None):
    # 预处理
    if clear_params[0] is not None:
        module.clear_params(clear_params[0])
    tree_apply(lambda m: m._status.set(status[0]), ..., tree=module)

    yield       # ← 在这里交出控制权，执行 with 块内的代码

    # 后处理（清理）
    if clear_params[1] is not None:
        module.clear_params(clear_params[1])
    ...

# 用法：
with step(model, STATUS.INIT, clear_params=(None, VodeParam.Cache)):
    energy = model.energy()
#   with 块执行完后，自动清除 Cache
```

**等价于手动写 `__enter__` + `__exit__`**：

```python
class step:
    def __enter__(self):
        # yield 之前的代码
    def __exit__(self, *args):
        # yield 之后的代码
```

`@contextmanager` 让这个模式只需要一个函数加两段代码，比手写类简洁得多。

### 10.4 `IntEnum` —— 整数枚举

```python
# pcx/core/_module.py:149-152
class MODE(IntEnum):
	NONE = 0
	TRAIN = 1
	EVAL = 2
```

`IntEnum` = `int` + `Enum`。可以当作普通整数使用（`MODE.TRAIN == 1` 是 `True`），但有语义化名称和类型安全（不能随便赋值为 `5`）。

#### 枚举成员是枚举类的实例（Enum 特有）

`IntEnum`（及所有 `Enum` 子类）的成员本身就是枚举类的**实例**，而非普通类属性。这是 `Enum` 特有的行为，源于其元类 `EnumType`：它在创建类时会拦截 `TRAIN = 1` 这样的赋值，把每个条目转换成 `MODE` 的一个实例，只是该实例的 `.value = 1`。

```python
# 已验证
MODE.TRAIN                      # <MODE.TRAIN: 1>，本身就是 MODE 实例
MODE.TRAIN.value                # 1
type(MODE.TRAIN)                # <enum 'MODE'>
isinstance(MODE.TRAIN, MODE)    # True
```

**对类型标注的影响**：正因如此，`Module.MODE.TRAIN` 的类型就是 `MODE`，能匹配 `value: MODE | None` 标注：

```python
# pcx/core/_module.py:157,178
def mode(self, value: MODE | None) -> MODE | None: ...

self.mode(Module.MODE.TRAIN)   # 传入的值类型是 MODE，匹配标注 ✓
```

**对比普通类**：普通类的类属性只是赋值时那个对象，不会变成该类的实例：

```python
class PlainInt:
    TRAIN = 1

type(PlainInt.TRAIN)                  # int
isinstance(PlainInt.TRAIN, PlainInt)  # False -- 与 PlainInt 无关
```

| 写法                            | `类.属性` 的类型 | 是该类的实例？ |
| ------------------------------- | ---------------- | -------------- |
| `class Mode(IntEnum): TRAIN=1`  | `Mode`           | ✅             |
| `class Color(Enum): RED=1`      | `Color`          | ✅             |
| `class PlainInt: TRAIN=1`       | `int`            | ❌             |

所以 `Module.MODE.TRAIN` 能符合 `MODE | None` 标注，**同时依赖**两点：标注描述的是值的类型（与访问路径无关，通用原则）+ Enum 的元类把成员做成了实例（Enum 特有）。换个普通类，同样的 `类.属性` 访问形式就不再成立。

## 11. 标准库（四）：`types.UnionType`

Python 3.10+ 支持用 `|` 写联合类型（如 `int | str`），运行时它的类型是 `types.UnionType`：

```python
from types import UnionType

# 用户传入的可能是单个类型，也可能是联合类型
def check_type(value, expected):
    # expected 可能是 int，也可能是 int | str | float
    if isinstance(expected, type | UnionType):
        return isinstance(value, expected)
    else:
        raise TypeError("expected 必须是类型或类型联合")


# 使用
check_type(42, int)           # True
check_type("hi", int | str)   # True
check_type(3.14, int | str)   # False
```

> `int` 和 `str` 都是 `type`类型，而 `int | str` 是 `UnionType` 类型

**关键点**：`isinstance(obj, int | str)` 在 Python 3.10+ 是合法的，等价于 `isinstance(obj, (int, str))`

#### pcx示例：`str.rsplit` / `str.split` —— 字符串分割

```python
# pcx/predictive_coding/_vode.py:122 —— 从右分割（递归处理链式变换）
tform, _t = tform.rsplit(":", 1)
# "u:se:zero"  rsplit(":", 1)  →  ("u:se", "zero")
# "u:se"       rsplit(":", 1)  →  ("u", "se")

# pcx/predictive_coding/_vode.py:265 —— 逗号分割目标
for _target in _targets.split(","):
    _target = _target.strip()      # 去掉空格
```

**`rsplit` vs `split`**：`rsplit(":", 1)` 从**右边**割一刀，`split(":", 1)` 从**左边**割一刀。链式变换 "u:se:zero" 需要从右向左处理（先算出 `u:se` 的结果，再传给 `zero`），所以用 `rsplit`。
