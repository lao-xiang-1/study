# Python 高级语法（一）：类型注解 (Type Annotations)

> 基于 PCX 项目实际代码，介绍 Python 类型注解的高级用法。

## 0. PEP 484 —— 类型注解的"宪法"

**PEP 484**（Python Enhancement Proposal 484）由 Guido van Rossum 等人于 2014 年提出，随 Python 3.5（2015.09）正式引入，是 Python 类型注解体系的**奠基规范**。

### PEP 484 定义了哪些东西？

| 内容           | 说明                                                      |
| ------------ | ------------------------------------------------------- |
| 函数注解语法       | `def f(x: int) -> str` 的标准语义                            |
| `typing` 模块  | `TypeVar`、`Generic`、`Union`、`Optional`、`Callable` 等核心工具 |
| `TypeVar` 定义 | 名字约定（变量名=字符串参数）、`bound=`、协变/逆变                          |
| 前向引用         | 用字符串 `"ClassName"` 解决类定义未完成的问题                          |
| 泛型类          | `class Stack(Generic[T])` 语法                            |
| `.pyi` 存根文件  | 类型存根（stub file）格式                                       |
| 渐进式类型        | 不强制、可逐步添加（gradual typing）                               |

### 为什么重要？

PEP 484 之前，类型注解语法已在 Python 3.0 存在（函数注解），但没有统一用途。PEP 484 统一了标准，催生了整个类型检查生态：

- **mypy**：首个 Python 静态类型检查器（Dropbox 出品）
- **pyright / pyre / pytype**：后续竞品
- **IDE 能力**：PyCharm、VSCode 的自动补全、重构、错误提示均基于此

### 类型系统的后续演进

PEP 484 只是起点，后续 PEP 逐步增强了类型系统：

| PEP | 内容 | Python 版本 |
|-----|------|------------|
| PEP 483 | 类型系统理论基础（PEP 484 的理论前置） | — |
| **PEP 484** | **类型注解 + typing 模块** | **3.5** |
| PEP 526 | 变量注解语法：`x: int = 5` | 3.6 |
| PEP 544 | `Protocol` 结构化子类型（鸭子类型检查） | 3.8 |
| PEP 585 | `list[int]` 代替 `List[int]`（泛型内置类型） | 3.9 |
| PEP 604 | `X \| Y` 代替 `Union[X, Y]` | 3.10 |
| PEP 612 | `ParamSpec` 保留装饰器函数签名 | 3.10 |
| PEP 646 | `TypeVarTuple` 可变数量泛型参数 | 3.11 |
| PEP 673 | `Self` 类型（返回自身类型） | 3.11 |
| PEP 695 | 新式泛型语法 `def f[T](x: T) -> T` | 3.12 |

## 1. 基础类型注解

Python 3.5+ 引入了类型注解（Type Hints），允许在代码中标注变量、参数和返回值的预期类型。

```python
# 变量注解
x: int = 5
name: str = "hello"

# 函数注解
def greet(name: str) -> str:
    return f"Hello, {name}"
```

**要点**：类型注解在运行时**不被强制检查**，主要用于 IDE 提示和静态类型检查器（mypy, pyright）。

## 2. Callable —— 函数类型注解

### 2.1 基本语法

`Callable[[参数类型列表], 返回值类型]` 用于描述一个函数的类型签名。

```python
from typing import Callable
import jax

# 来自 pcx/predictive_coding/_vode.py:173-174
# energy_fn 是一个函数，接收 Vode 和 RandomKeyGenerator，返回 jax.Array
energy_fn: Callable[["Vode", RandomKeyGenerator], jax.Array]
```

**解读**：`Callable[[A, B], R]` 表示一个接受 `(A, B)` 两个参数、返回 `R` 的函数。

## 3. 前向引用 —— 字符串形式的类型

### 3.1 为什么需要前向引用？

当类型注解引用的类**尚未定义完成**时，需要用字符串形式（forward reference）。

```python
# pcx/predictive_coding/_vode.py:100-101,160
class Vode(EnergyModule):
    # Vode 内部的方法需要引用 Vode 自身 —— 但此时 Vode 还没定义完！
    # 解决方式：用字符串 "Vode" 代替 Vode

    def apply_set_transformation(
        self,
        node: "Vode",   # 前向引用：字符串形式的类型名
        tform: str,
        key: str,
        value: Any | None = None,
        rkg: RandomKeyGenerator = RKG,
    ) -> Any | None:
```

### 3.2 Python 3.11+ 的改进

从 Python 3.11 开始，可以使用 `from __future__ import annotations`，让**所有**注解自动变成字符串形式：

```python
from __future__ import annotations  # 放在文件最顶部

# 之后可以省略引号：
def apply_set_transformation(
    self,
    node: Vode,    # 不再需要 "Vode"
    ...
) -> Any | None:
```

## 4. `Type[T]` —— 类型本身作为参数

`Type[T]` 表示传递的不是某个类的**实例**，而是**类本身**。
> 可以用`type[T]`（t 小写）表示简写

```python
# pcx/predictive_coding/_vode.py:177-178
class Vode(EnergyModule):
    def __init__(
        self,
        ...
        param_type: type[VodeParam] = VodeParam,  # 传入类型本身，而非实例
        #           ^^^^^^^^^^^^^^^  type[T] 是 Type[T] 的简写
        *param_args,
        **param_kwargs,
    ):
        super().__init__()
        self.h = param_type(*param_args, **param_kwargs)
        #        ^^^^^^^^^^ 用传入的类型来构造实例
```

**含义**：`param_type` 的预期值是 `VodeParam` 这个类（或其子类），而不是 `VodeParam` 的一个实例。
>这允许调用者传入自定义的类（只需继承自VodeParam）

## 5. TypeVar —— 泛型类型变量

`TypeVar` 允许编写**泛型**代码 —— 保持输入和输出类型的一致性。

```python
# pcx/core/_module.py:18
from typing import TypeVar

T = TypeVar("T")
# 定义了一个类型变量 T，可以表示任意类型
# 按照规范，TypeVar的第一个参数 和 变量名必须一致

class BaseModule(metaclass=_BaseModuleMeta):
    def submodules(self, *, cls: Type[T] | None = None) -> Generator[T, None, None]:
        # 很显然，前后两个T是一样的，TypeVar就只是允许你这么写而已
        # 如果 cls=Linear，则返回 Generator[Linear, None, None]
        # 如果 cls=Vode，则返回 Generator[Vode, None, None]
        ...
```

## 6. 联合类型 X | Y 与 Union

表示"X 或 Y 都可以"。

### 6.2 旧式写法：`Union[X, Y]`

```python
from typing import Union

# Union[str, None]  等价于  str | None
# Union[int, float] 等价于  int | float
```

### 6.3 `Optional[T]` —— 可为 None 的类型

`Optional[T]` 是 `Union[T, None]` 的简写，等价于 `T | None`（Python 3.10+）。

```python
# 以下三种写法等价：
# Optional[jax.Array]
```

## 8. `Sequence[T]` 与 `Dict[K,V]` —— 容器类型

### 8.1 `Sequence[T]`：只读序列

### 8.2 `Dict[K, V]`：字典类型

`Dict[K, V]` 要求所有键是同一种类型，所有值也是同一种类型。如果需要异构字典，可以用 `TypedDict` 或 `Union`。

#### 同构字典


#### 异构字典：`TypedDict`

当键名预先已知、且每个键对应不同类型值时，使用 `TypedDict`：

## 7. `Generator[Y, S, R]` —— 生成器类型注解

### 7.1 为什么 Generator 有三个类型参数？

普通函数的返回值只有一个类型（`-> int`），但生成器不同——它是一个**双向通信通道**：

| 操作 | 方向 | 对应类型参数 |
|------|------|-------------|
| `yield x` | 生成器 → 调用方（产出值） | **Y** (YieldType) |
| `x = yield` | 调用方 → 生成器（发送值） | **S** (SendType) |
| `return x` | 生成器 → 调用方（最终返回值） | **R** (ReturnType) |

```python
from typing import Generator

# Generator[YieldType, SendType, ReturnType]
```

### 7.2 最常见形式：`Generator[T, None, None]`

在绝大多数场景中，生成器**只产出值**，既不接收 `send()`，也不 `return` 最终值：

```python
# pcx/core/_module.py:120
def submodules(self, *, cls: Type[T] | None = None) -> Generator[T, None, None]:
    """Return the children submodules of the given type."""
    cls = cls or BaseModule
    _leaves, _ = eqx.tree_flatten_one_level(self)

    yield from filter(
        lambda x: isinstance(x, cls),
        jtu.tree_leaves(_leaves, is_leaf=lambda x: isinstance(x, cls)),
    )
```

**解读**：`Generator[T, None, None]` 表示：
- **Y = T**：产出值的类型是 `T`（由 `cls` 参数决定具体类型）
- **S = None**：不接受 `send()` 传值（调用方不应向生成器发送数据）
- **R = None**：不通过 `return` 返回最终值（`StopIteration.value` 为空）

> 这是 Python 生成器类型注解中**最常见的模式**——95% 的生成器都属于这类"仅产出"生成器。

### 7.3 `Generator` vs `Iterator` vs `Iterable`

这三个类型经常被混淆，关键区别如下：

```python
from typing import Generator, Iterator, Iterable

# Iterable[T]  —— 最宽泛：能被 for 遍历即可（有 __iter__）
# Iterator[T]   —— 中间层：有 __next__ 方法，手动迭代
# Generator[Y,S,R] —— 最具体：由 yield 定义的生成器函数返回

def foo() -> Iterable[int]:      # 可以是 list、tuple、generator 等任意可迭代对象
    return [1, 2, 3]

def bar() -> Iterator[int]:      # 返回一个迭代器（generator 也满足）
    return iter([1, 2, 3])

def baz() -> Generator[int, None, None]:  # 明确是一个生成器函数
    yield 1
    yield 2
    yield 3
```

**选择建议**：
- 如果只是想让调用方能 `for x in foo()`，用 `Iterator[T]` 最合适（既宽松又准确）
- 如果函数体内用了 `yield`，用 `Generator[T, None, None]` 最精确
- 尽量不要用 `Iterable[T]` 作为返回值——它太宽泛，掩盖了实现细节

### 7.4 进阶：接收 `send()` 的生成器

少数场景下，生成器通过 `yield` 接收外部传入的值：

```python
from typing import Generator

def accumulator() -> Generator[int, int, str]:
    """
    产出累计值 (int)，
    接收增量 (int)，
    最终返回总结 (str)。
    """
    total = 0
    while True:
        delta = yield total       # 产出 total，接收 delta
        if delta is None:         # send(None) 或 next() 时终止
            return f"Final: {total}"
        total += delta

acc = accumulator()
print(next(acc))       # 0 —— 启动生成器，产出初始 total
print(acc.send(5))     # 5 —— 传入 5，产出更新后的 total
print(acc.send(3))     # 8 —— 传入 3，产出更新后的 total
try:
    acc.send(None)     # 触发 return，StopIteration("Final: 8")
except StopIteration as e:
    print(e.value)     # "Final: 8"
```

> **提示**：`Generator[int, int, str]` 这种三参数都不为 None 的情况在实际代码中非常罕见（Python 3.10+ 的 `asyncio` 和协程更常用）。大多数时候你只需要 `Generator[T, None, None]`。
