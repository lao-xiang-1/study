# 设备树（Device Tree）

设备树（Device Tree）是一种用于描述硬件的数据结构。Linux 内核启动时通过它识别板载外设，而无需把硬件信息硬编码进内核，因此**同一内核镜像可以适配不同开发板**。

---

## 1 核心概念

- **DTS（Device Tree Source）**：设备树源文件，文本格式，后缀 `.dts`。
- **DTSI（Device Tree Source Include）**：公共头文件，可被多个 `.dts` 包含，后缀 `.dtsi`。
- **DTB（Device Tree Blob）**：DTS 经 `dtc` 编译后的二进制文件，由 Bootloader 加载并传递给内核。
- **FDT（Flattened Device Tree）**：扁平设备树，即 DTB 在内存中的形态。
- **DTC（Device Tree Compiler）**：设备树编译器，负责 DTS ↔ DTB 转换。
- **Device Tree Overlay**：设备树插件/覆盖层，用于在运行时动态追加或修改节点。

---

## 2 基本语法

### 2.1 节点（Node）

节点描述一个硬件单元，格式为：

```dts
label: node-name@unit-address {
    /* 属性 */
};
```

- `label`：标签，便于其他位置引用。
- `node-name`：节点名，如 `memory`、`soc`、`i2c`。
- `unit-address`：设备地址，通常与 `reg` 首地址一致；无地址可省略。

### 2.2 属性（Property）

属性用于描述节点特征，常见值类型：

| 类型 | 示例 | 说明 |
| --- | --- | --- |
| 字符串 | `compatible = "rockchip,rk3588";` | 双引号包裹 |
| 32 位整数列表 | `reg = <0x0 0x10000000>;` | 尖括号，每个数 32 bit |
| 字节序列 | `mac-address = [00 11 22 33 44 55];` | 十六进制字节 |
| 引用 | `interrupt-parent = <&gic>;` | 指向标签 |

### 2.3 标签与引用（Label & Reference）

```dts
gic: interrupt-controller@fee00000 {
    ...
};

some-device@0 {
    interrupt-parent = <&gic>;
};
```

- `&gic` 表示引用 `gic` 标签对应的节点。
- 追加/修改已有节点可用引用语法：

```dts
&gic {
    status = "okay";
};
```

### 2.4 包含文件

```dts
#include "rk3588.dtsi"
#include "rk3588-lubancat-5io.dtsi"
```

> `.dts` 里常用 C 语言风格的 `#include`，`.dtsi` 中一般存放 SoC 级公共定义。

---

## 3 常用属性

- **`compatible`**：驱动匹配字符串，如 `"rockchip,rk3588-lubancat-5io"`。
- **`model`**：设备型号，给人阅读的描述。
- **`reg`**：设备寄存器基地址与长度，格式 `<address size>`。
- **`#address-cells`**：子节点 `reg` 中地址字段占用 32 位单元数。
- **`#size-cells`**：子节点 `reg` 中长度字段占用 32 位单元数。
- **`interrupts`**：中断号及触发方式。
- **`interrupt-parent`**：指向中断控制器节点。
- **`status`**：节点使能状态，`"okay"` 启用，`"disabled"` 禁用。
- **`phandle`**：唯一标识，用于其他属性引用。

---

## 4 设备树插件（Device Tree Overlay）

Overlay 允许在不重新编译主 DTB 的情况下，动态叠加或修改节点。典型结构：

```dts
/dts-v1/;
/plugin/;

/ {
    fragment@0 {
        target = <&pcie2x1l2>;
        __overlay__ {
            status = "disabled";
        };
    };
};
```

- `/plugin/;` 声明这是一个 Overlay。
- `fragment@N`：一个补丁片段。
- `target`：指向要修改的节点。
- `__overlay__`：要合并到目标节点的内容。

---

## 5 常用命令

### 5.0 dtc 常用参数

| 参数 | 说明 |
| --- | --- |
| `-I <format>` | 指定输入格式，如 `dts`、`dtb`、`fs` |
| `-O <format>` | 指定输出格式，如 `dtb`、`dts`、`asm` |
| `-o <file>` | 指定输出文件名 |
| `-@` | 生成符号信息，供 Overlay 使用 |
| `-i <dir>` | 指定 `#include` 搜索路径 |
| `-H <format>` | 指定 `phandle` 格式，如 `epapr`、`legacy` |

### 5.4 常用命令模板

```bash
# DTS → DTB
dtc -I dts -O dtb -o output.dtb input.dts

# DTB → DTS
dtc -I dtb -O dts -o output.dts input.dtb

# 检查语法
dtc -I dts -O dtb input.dts > /dev/null
```

### 实际应用
#### 5.1 编译 dtb

```bash
dtc rk3588-lubancat-5io-xfce.dts -O dtb -o rk3588-lubancat-5io.dtb
```

#### 5.2 编译 overlay

```bash
dtc disable-pcie-overlay.dts -@ -I dts -O dtb -o disable-pcie-overlay.dtbo
```

> `-@` 用于生成 Overlay 所需的符号信息。

#### 5.3 反编译当前 dtb

```bash
sudo dtc -I dtb -O dts rk3588-lubancat-5io.dtb > rk3588-lubancat-5io.dts
```

> [!关于`>`符号]
> `rk3588-lubancat-5io.dtb > rk3588-lubancat-5io.dts` 中的 `>` 是 **Shell 重定向**，对所有把结果输出到标准输出（stdout）的命令都通用，不是 `dtc` 特有的。
> 
> 不过有两种细节要注意：
> 
> 1. **执行顺序不同**
>    - `dtc ... > file`：Shell 先创建/清空 `file`，然后运行 `dtc`，把屏幕输出写进文件。
>    - `dtc ... -o file`：由 `dtc` 自己决定何时打开、写入 `file`。
> 
> 2. **配合 `sudo` 时容易踩坑**
>    ```bash
>    sudo dtc -I dtb -O dts rk3588-lubancat-5io.dtb > rk3588-lubancat-5io.dts
>    ```
>    这里的 `>` 是由当前用户的 Shell 处理的，不是 `sudo`。如果目标目录需要 root 权限，重定向会失败；而 `sudo dtc ... -o file` 则是 root 权限下的 `dtc` 自己写文件。


## 6 dts最小示例

```dts
/dts-v1/;

/ {
    model = "Rockchip RK3588 LubanCat 5IO";
    compatible = "rockchip,rk3588-lubancat-5io", "rockchip,rk3588";

    #address-cells = <2>;
    #size-cells = <2>;

    memory@0 {
        device_type = "memory";
        reg = <0x0 0x0 0x0 0x80000000>; /* 2 GiB */
    };

    chosen {
        bootargs = "console=ttyS2,1500000n8";
        stdout-path = "serial2:1500000n8";
    };

    soc: soc@0 {
        compatible = "simple-bus";
        ranges;
    };
};
```
