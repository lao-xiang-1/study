# 文件链接：硬链接、符号链接与 uv 的 link-mode

## 0. 前置：inode 与目录项

在 Unix/Linux 上，文件数据与元数据由 **inode（索引节点，index node）** 描述，inode 有一个唯一的编号。**目录本身只是一张表**，内容是 `文件名 → inode 编号` 的映射。

> 关键认知：我们平时说的"一个文件"，其实只是**一个目录项（directory entry）指向某个 inode**。文件名不是文件的身份，inode 才是。

inode 里维护一个 **引用计数（link count）**，记录有多少个目录项指向它。

## 1. 硬链接（Hard Link）

**硬链接就是"给同一个 inode 再起一个名字"**，即在目录表里新增一条 `名字 → inode` 的记录。

- 两个名字**完全平等**，没有"原文件 / 副本"之分。
- 共享同一个 inode ⇒ 内容、权限、属主、时间戳**全部共享**；改其中一个，另一个立刻同步变化。
- 删除任意一个名字，只是把 link count 减 1；**只有计数归零时**，inode 和数据块才被真正释放。
- 判断方法：`ls -l` 第二列（链接数）`> 1`。

**限制：**

- **不能跨文件系统**——inode 编号只在单个文件系统（分区）内唯一。
- 大多数系统**不允许给目录建硬链接**（会形成环，破坏目录树的树形结构）。

## 2. 符号链接（Symbolic Link / 软链接）

**符号链接是一个独立的特殊文件**，它自己的内容是"目标路径"这个**字符串**。

- 拥有**自己的 inode 和权限**（`ls -l` 显示为 `lrwxrwxrwx`，`名字 -> 目标`）。
- 查找路径时才去解析目标，因此：
  - 可以**跨文件系统**；
  - 可以指向**目录**；
  - 可以指向**不存在的路径**（悬空链接 dangling symlink）。
- 删除**链接本身**不影响目标；删除**目标**则链接悬空失效。

## 3. 对比

| 维度 | 硬链接 | 符号链接 |
| :--- | :--- | :--- |
| 本质 | 同一 inode 的另一个名字 | 内容为路径字符串的特殊文件 |
| 跨文件系统 | ✗ | ✓ |
| 指向目录 | ✗（一般禁止） | ✓ |
| 目标删除后 | 仍然有效（数据还在） | 悬空失效 |
| 是否共享 inode | ✓ | ✗（自己独立 inode） |
| 空间占用 | 几乎为 0 | 极小的一个特殊文件 |
| 破坏方式 | 改一个名字 = 改所有名字 | 只影响该链接 |

## 4. Windows 上的对应物

Windows（NTFS）的术语和命令与 Linux 不同，用 `mklink` 系列：

| 类型 | 命令 | 限制 |
| :--- | :--- | :--- |
| 硬链接 | `mklink /H 链接 目标`（或 `fsutil hardlink create`） | 仅**同一卷**；不能链接目录 |
| 符号链接（文件） | `mklink 链接 目标` | 需**管理员权限**或**开发者模式**；可跨卷 |
| 符号链接（目录） | `mklink /D 链接 目标` | 同上 |
| 目录联接（Junction） | `mklink /J 链接 目标` | 只能目录、只能**本地卷**、绝对路径；**不需要管理员权限** |

> Junction 是 Windows 上最常用的"目录软链接"，但它不能跨盘、只能本地。
> 正因为 Windows 的 symlink 有权限门槛，uv 在 Windows 上默认选择**硬链接**而不是符号链接。

验证某个文件是否被硬链接（Windows）：

```powershell
fsutil hardlink list "D:\proj\.venv\Lib\site-packages\torch\lib\torch_cuda.dll"
# 若输出两条路径（一条在 .venv，一条在 uv cache）→ 是硬链接，磁盘只存了一份
```

> 注意：资源管理器显示的是**逻辑大小**，硬链接在每个路径下都会显示完整大小，所以"每个 venv 4.8 GB"并不代表真的复制了。

## 5. uv 的 link-mode

### 5.1 背景：缓存 → venv

uv 把下载/构建好的包**解包到全局缓存**（`uv cache dir`；Windows 默认 `C:\Users\<用户>\AppData\Local\uv\cache`），创建或同步虚拟环境时，再把缓存里的文件**链接**进 `.venv\Lib\site-packages`。

**用什么方式"链接"，就是 `link-mode`。** 它的目的：多环境之间**去重**、省磁盘、安装更快。

> uv 官方说明：缓存目录最好与 Python 环境位于**同一文件系统**，否则 uv 无法从缓存链接文件，只能退化为**慢速复制**。

### 5.2 四种模式

| 值 | 含义 | 特点 |
| :--- | :--- | :--- |
| `clone` | 写时复制（Copy-on-Write），从缓存克隆 | 依赖文件系统支持（macOS APFS、Linux Btrfs/XFS reflink）；省空间且修改安全 |
| `copy` | 真复制 | 最安全、最慢、最占空间；pip 的传统行为 |
| `hardlink` | 硬链接 | 省空间、快；**要求缓存与目标同一文件系统** |
| `symlink` | 符号链接 | uv **明确不推荐**（见下） |

### 5.3 默认值

- **macOS / Linux：`clone`**（写时复制）
- **Windows：`hardlink`**

### 5.4 `symlink` 的警告（官方原文）

> WARNING: The use of symlink link mode is discouraged, as they create tight coupling between the cache and the target environment. For example, clearing the cache (`uv cache clean`) will break all installed packages by way of removing the underlying source files. Use symlinks with caution.

即：软链接让 venv **强依赖缓存**，一旦 `uv cache clean`，已安装的包会因为源文件被删而全部损坏。

### 5.5 跨文件系统回退

当缓存与目标不在同一文件系统时（硬链接无法创建），uv 会退化为复制并打印警告：

```
warning: Failed to hardlink files; falling back to full copy.
This may lead to degraded performance.
If the cache and target directories are on different filesystems, hardlinking may not be supported.
If this is intentional, set `export UV_LINK_MODE=copy` or use `--link-mode=copy` to suppress this warning.
```

> 在 Windows 上最常见的触发场景：**缓存默认在 `C:`，而项目在 `D:` / `E:`**。NTFS 硬链接只能在同一卷内创建。
> 这是**性能警告，不是错误**——包已正确安装，运行行为不受影响。

**推荐解决方式**：把缓存目录设到项目所在的同一磁盘，恢复硬链接，而不是简单关掉警告。

```powershell
uv cache dir                       # 查看当前缓存位置
setx UV_CACHE_DIR D:\uv-cache      # 永久设置到 D 盘（需重开终端生效）
```

### 5.6 配置方式

```bash
# 1) 命令行参数
uv pip install --link-mode=copy <pkg>
uv sync --link-mode=copy

# 2) 环境变量
export UV_LINK_MODE=copy           # Windows: setx UV_LINK_MODE copy
```

```toml
# 3) 项目级：pyproject.toml
[tool.uv]
link-mode = "copy"
```

```toml
# 4) 用户级：uv.toml（Linux/macOS ~/.config/uv/uv.toml；Windows %APPDATA%\uv\uv.toml）
link-mode = "copy"
```

## 6. 一句话总结

- **硬链接**：同一个 inode 的多个名字，同文件系统内、省空间，改一个全变。
- **软链接**：指向路径的独立文件，可跨系统、可悬空，目标没了就失效。
- **uv 的 link-mode**：选择把缓存里的包"如何搬进" venv——默认 macOS/Linux 用 `clone`、Windows 用 `hardlink`；跨盘会退化为 `copy` 并告警；`symlink` 不推荐。
