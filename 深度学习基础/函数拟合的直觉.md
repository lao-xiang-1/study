
一个神经网络能拟合的函数是有限的，这取决于网络结构和参数量。
举个极端的例子：现在的llm也可以认为是一个函数。而我们让一个只含128个参数的单层mlp去拟合GPT-6，怎么都无法实现。
我们训练一个模型，本质是让这个模型去拟合 数据集 的输入输出。利用反向传播一步步减小损失，直到到达一个局部最优点。

而我们想实现的持续学习，某种意义上要让他拟合任何函数，也就是对于任何新加入的数据集，都能做到完美拟合，而不忘记原有的知识。
那么一个固定的网络是完全不够的 —— 它的拟合能力必然有极限。
一个模型必须要不断扩展参数数量，甚至是改变自身的结构，才能做到持续学习。

~~一种思路：该模型本身包含了大量参数（它的 完整拟合能力 超过了最开始的训练任务），在实际的使用过程中，不断学习新知识，直到饱和。~~

**持续学习的目标不是"拟合任意函数"，而是"在任务分布上不断获取新知识且不破坏旧的"。在最坏情况（任务任意）下，这要求容量随任务信息量增长——这是极限约束。**
但在实践中，最先碰到的瓶颈是**新数据的干扰**，而非容量饱和。

## 拟合函数

要判断 **A 类函数能不能表示 B 类函数**,标准做法是:把 B 的权重**冻住当标准答案**,然后用梯度下降去调 A 的参数,看 A 的输出能不能逼近 B 的输出。

- 误差能降到 ~0 → B 里的每个函数都在 A 的范围里 → **B ⊆ A**
- 无论怎么训练都停在一个明显的非零残差 → 强烈提示 B 里有 A 表示不了的东西

所谓"**两边互相拟合**",就是把这件事**两个方向各做一遍**:

| | 冻住的(标准答案) | 训练的(模仿者) | 在问的问题 |
|---|---|---|---|
| A 方向 | 多头 | 单头 | 多头 ⊆ 单头 ? |
| B 方向 | 单头 | 多头 | 单头 ⊆ 多头 ? |

两个方向都失败 → 两者不是包含关系,而是**两个不同的函数类**。

## 具体脚本

**1. 两个类,参数预算相同**([check_mha_vs_sha.py:19-56](temp/check_mha_vs_sha.py#L19-L56))

$d=8, h=4, d_h=2$,两边都是 256 个参数:

- 多头:`Wq/Wk/Wv` 各 `[4, 8, 2]` = 64 → 192,加 `Wo` `[8,8]` = 64,共 256
- 单头:`Wq/Wk/Wv` 各 `[8, 8]` = 64 → 192,加 `Wo` 64,共 256(外加一个温度参数)

预算刻意做成一样 —— 否则"谁更强"就变成比参数多少了,没有意义。

**2. 输入是一批随机序列**([check_mha_vs_sha.py:63](temp/check_mha_vs_sha.py#L63))

```python
X = torch.randn(B, n, d)      # 256 条序列 × 6 个 token × 8 维
```

**这一步是整个实验成立的关键。** "两个函数相等"必须对**所有**输入成立。如果只喂一个输入,那就是个欠定问题:256 个参数去拟合 48 个输出值,怎么都能拟合上,什么也说明不了。

现在有 $256 \times 6 \times 8 = 12288$ 个输出值要匹配,约束远多于参数。**在这种情况下还能把误差降到 0,才真的意味着两者是同一个函数**,而不是参数多到把答案背下来了。

**3. 冻住标准答案**([check_mha_vs_sha.py:66-69](temp/check_mha_vs_sha.py#L66-L69))

```python
with torch.no_grad():
    Y_mha = mha(X).clone()      # 算出来就固定,不参与梯度
```

`torch.no_grad()` + `clone()` 让它变成一个常数张量。训练过程中只有模仿者的参数在动。

**4. 训练循环**([check_mha_vs_sha.py:74-79](temp/check_mha_vs_sha.py#L74-L79))

就是最普通的 MSE + Adam,`sha(X)` 是候选输出,`Y_mha` 是目标。

**5. 残差按目标方差归一化**([check_mha_vs_sha.py:83](temp/check_mha_vs_sha.py#L83))

```python
print(f"... mse={r:.4e}  ({r / target_var * 100:.2f}% of target variance)")
```

`mse=0.0907` 这个数字本身没有意义,因为你不知道目标输出的量级。除以 `target_var` 之后:25.90% 意思是"**单头最好也只能解释掉多头输出的 74% 的方差,剩下 26% 无论如何都表示不出来**"。这才有可比性。

**6. 5 次随机重启 —— 这一步最重要**([check_mha_vs_sha.py:72](temp/check_mha_vs_sha.py#L72))

梯度下降只保证局部最优,所以"拟合失败"有两种可能:

- (a) 这个函数类**真的表示不了**
- (b) 只是**掉进了坏的局部最优**

为了排除 (b),用 5 个不同随机初始化各训一遍,取最好的那个。**如果 5 次全都停在同一个值(25.90%,小数点后四位完全一致),基本可以排除 (b)** —— 因为如果只是局部最优的锅,不同初始化应该落在不同的坑里,残差会散开,不会这么整齐地撞在同一个数上。

**7. 给单头一个可学习的温度**([check_mha_vs_sha.py:47-48](temp/check_mha_vs_sha.py#L47-L48))

单头按惯例除 $\sqrt{d}=\sqrt{8}$,多头每个 head 除 $\sqrt{d_h}=\sqrt{2}$。这个温度差异会人为地让单头吃亏。所以给单头一个 `exp(log_tau)` 让它自己选尺度,**把这个混淆因素排除掉**,剩下的差异才是结构性差异。

**8. C 段的秩检查**([check_mha_vs_sha.py:106-111](temp/check_mha_vs_sha.py#L106-L111))

这一段**不是拟合实验,是硬约束**。softmax 之前那个 score 矩阵 $S = XW_QW_K^\top X^\top$ 的秩被 $W_QW_K^\top$ 卡住:

- 单头:$W_QW_K^\top$ 是 $8\times8$ 乘 $8\times8$,秩可达 **8**
- 每个 head:$W_Q^i(W_K^i)^\top$ 是 $8\times2$ 乘 $2\times8$,秩最多 **2**

所以单头能表达的 score 矩阵,根本不在多头的取值范围里 —— 这是 B 方向也失败的**结构性原因**,和优化无关。

**9. 最后打印每个 head 的注意力权重**([check_mha_vs_sha.py:113-125](temp/check_mha_vs_sha.py#L113-L125))

直接展示"h 组独立权重"这个机制:同一个 query,4 个 head 给出的分布差很多(某个 key 位置上最大差 0.795),而单头只能有一行。

## 这个方法本身的局限(重要)

得说清楚,**拟合失败不等于证明**:

- **拟合成功** → 确定的证明。你找到了具体参数,包含关系就成立了。
- **拟合失败** → 只是**强证据**。理论上仍可能存在一个极难优化的解,梯度下降找不到。

所以这个脚本的正确用法是:**用拟合实验发现可疑之处,再用结构性论证(比如 C 段的秩)把它钉死**。C 段那个秩的论证是确定的,拟合实验是它的佐证 —— 这也是我为什么在报告结论时把两个都放上。
