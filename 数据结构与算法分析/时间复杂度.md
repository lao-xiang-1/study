# 时间复杂度（Time Complexity）

时间复杂度用于描述算法执行时间随输入规模增长的变化趋势，反映算法的效率高低。通常使用**大 O 记号（Big-O Notation）**表示，关注的是当 $n \to \infty$ 时算法耗时的增长量级，而非具体的执行时间。

> 大 O 记号描述的是算法耗时的**上界**，即最坏情况下的增长趋势。

---

## 1 常见时间复杂度

### 1.1 $O(1)$ — 常数阶（Constant）

算法的执行时间不随输入规模 $n$ 的变化而变化，无论 $n$ 多大，操作次数都是固定的。

- **特点**：最快的复杂度，与数据规模无关
- **典型场景**：
  - 通过数组下标直接访问元素：`arr[i]`
  - 哈希表（Hash Table）的理想查找
  - 栈的 `push` / `pop` 操作
  - 交换两个变量的值

```python
# O(1) 示例：直接访问数组第 i 个元素
def get_element(arr, i):
    return arr[i]
```

---

### 1.2 $O(\log n)$ — 对数阶（Logarithmic）

当输入规模 $n$ 增大时，操作次数按对数速度增长。对数的底数通常取 2（二分场景），但在大 O 表示中底数不影响量级，统一写作 $\log n$。

- **特点**：效率极高，$n$ 翻数倍，操作次数只增加常数项
- **直观理解**：每次操作都能将问题规模**减半**
- **典型场景**：
  - 二分查找（Binary Search）
  - 平衡二叉搜索树的查找（如 AVL 树、红黑树）
  - 堆（Heap）的插入与删除

```python
# O(log n) 示例：二分查找
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

> 若 $n = 1024$，二分查找最多只需约 $\log_2 1024 = 10$ 次比较。

---

### 1.3 $O(n)$ — 线性阶（Linear）

算法的操作次数与输入规模 $n$ 成正比，$n$ 增大几倍，操作次数就增大几倍。

- **特点**：遍历一次数据，效率可接受
- **典型场景**：
  - 遍历数组或链表求和、查找最大值
  - 线性查找（Linear Search）
  - 两个集合的合并操作（遍历其中一个）

```python
# O(n) 示例：求数组最大值
def find_max(arr):
    max_val = arr[0]
    for num in arr:
        if num > max_val:
            max_val = num
    return max_val
```

---

### 1.4 $O(n \log n)$ — 线性对数阶（Linearithmic）

操作次数为 $n$ 乘以对数 $\log n$，增长速度比 $O(n)$ 快，但远好于 $O(n^2)$。

- **特点**：分治策略的典型复杂度，大量高效排序算法的时间复杂度
- **典型场景**：
  - 归并排序（Merge Sort）
  - 快速排序（Quick Sort）的平均情况
  - 堆排序（Heap Sort）
  - 基于分治的许多算法（如最近点对问题）

> 若 $n = 1000000$，$n \log n \approx 20000000$，而 $n^2 = 10^{12}$，差距悬殊。

---

### 1.5 $O(n^2)$ — 平方阶（Quadratic）

操作次数与 $n$ 的平方成正比。当 $n$ 翻倍时，操作次数变为 4 倍。

- **特点**：双重循环的典型结果，$n$ 较大时效率急剧下降
- **典型场景**：
  - 冒泡排序（Bubble Sort）
  - 选择排序（Selection Sort）
  - 插入排序（Insertion Sort）
  - 两重嵌套遍历（如枚举所有数对）

```python
# O(n^2) 示例：冒泡排序
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
```

---

### 1.6 其他常见复杂度

| 复杂度 | 名称 | 说明 |
|--------|------|------|
| $O(\sqrt{n})$ | 根号阶 | 如素数判定的试除法优化版 |
| $O(n^3)$ | 立方阶 | 三重循环，如 Floyd 最短路径算法 |
| $O(2^n)$ | 指数阶 | 如递归求解子集问题 |
| $O(n!)$ | 阶乘阶 | 如全排列问题 |

## 2 增长速度对比

以下是在不同数据规模下，各时间复杂度的操作次数对比：

| 复杂度 | $n = 10$ | $n = 100$ | $n = 1000$ | $n = 10^6$ |
|--------|----------|-----------|------------|------------|
| $O(1)$ | 1 | 1 | 1 | 1 |
| $O(\log n)$ | $\approx 3$ | $\approx 7$ | $\approx 10$ | $\approx 20$ |
| $O(n)$ | 10 | 100 | $10^3$ | $10^6$ |
| $O(n \log n)$ | $\approx 30$ | $\approx 664$ | $\approx 10^4$ | $\approx 2 \times 10^7$ |
| $O(n^2)$ | 100 | $10^4$ | $10^6$ | $10^{12}$ |
| $O(2^n)$ | $1024$ | $\approx 10^{30}$ | — | — |

> 上表可直观看出：$O(n^2)$ 在 $n = 10^6$ 时已达 $10^{12}$ 量级，远超现代计算机每秒约 $10^8$ 次操作的承受能力。

## 4 分析时间复杂度的基本原则

### 4.1 关注主导项

当表达式中存在多项时，只保留增长最快的项，省略系数和低阶项：

- $O(3n^2 + 2n + 5) \Rightarrow O(n^2)$
- $O(2n \log n + 100n) \Rightarrow O(n \log n)$

### 4.2 常见结构的复杂度

- **单层循环**：循环体执行 $n$ 次 → $O(n)$
- **双层嵌套循环**：各 $n$ 次 → $O(n^2)$
- **循环折半**：如 `i = n; while i > 0: i //= 2` → $O(\log n)$
- **递归分治**：如归并排序 $T(n) = 2T(n/2) + O(n)$ → $O(n \log n)$

### 4.3 最好、最坏与平均情况

- **最好情况（Best Case）**：输入数据最理想时的复杂度
- **最坏情况（Worst Case）**：输入数据最糟糕时的复杂度
- **平均情况（Average Case）**：所有可能输入的期望复杂度

> 通常所说的时间复杂度默认指**最坏情况**，因为它给出了算法效率的可靠上界。
