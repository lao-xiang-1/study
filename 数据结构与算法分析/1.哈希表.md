# 1 哈希表（Hash Table）

哈希表是一种高效的数据结构，通过哈希函数将键（key）映射到数组的特定位置，从而实现平均 O(1) 时间复杂度的查找、插入和删除操作。

---

## 1.1 什么是哈希表

### 1.1.1 定义与核心思想

**哈希表** = **数组** + **哈希函数**

核心思想：通过哈希函数将任意类型的键转换为数组索引，直接定位到存储位置，避免遍历。

**工作流程**：

```
key → hash(key) → index → array[index] = value
```

**图示**：

```
┌─────────────────────────────────────┐
│           哈希表 (Hash Table)        │
├─────────────────────────────────────┤
│                                     │
│  key: "apple"                       │
│   ↓                                 │
│  hash("apple") → 计算哈希值 7        │
│   ↓                                 │
│  7 % 表大小 → index = 2             │
│   ↓                                 │
│  array[2] = "水果"                   │
│                                     │
├─────────────────────────────────────┤
│  数组存储:                           │
│  [0]: ...                           │
│  [1]: ...                           │
│  [2]: "水果"  ← 存储位置             │
│  [3]: ...                           │
│  ...                                │
└─────────────────────────────────────┘
```

### 1.1.2 为什么需要哈希表

**与数组、链表的对比**：

| 操作 | 数组（有序） | 链表 | 二叉搜索树 | 哈希表 |
|------|-------------|------|-----------|--------|
| 查找 | O(log n) | O(n) | O(log n) | **O(1) 平均** |
| 插入 | O(n) | O(1)* | O(log n) | **O(1) 平均** |
| 删除 | O(n) | O(1)* | O(log n) | **O(1) 平均** |

> *链表插入/删除需要先找到位置 O(n)，找到后操作本身 O(1)

**关键点**：
- 哈希表在**平均情况**下提供 O(1) 操作，远优于其他数据结构
- 但**最坏情况**可能退化为 O(n)
- 适用于需要频繁查找、去重、计数的场景

### 1.1.3 基础 API

**Python 中的 dict 就是哈希表**：

```python
# 插入/更新
hashmap = {}
hashmap["name"] = "Alice"      # hashmap[key] = value
hashmap.update({"age": 25})    # 批量更新

# 查找
name = hashmap["name"]         # 直接访问，O(1)
age = hashmap.get("age", 0)    # 安全访问，不存在返回默认值

# 删除
del hashmap["age"]             # 删除指定键值对
age = hashmap.pop("age", 0)    # 删除并返回值

# 其他常用操作
"age" in hashmap               # 判断键是否存在，O(1)
hashmap.keys()                 # 所有键
hashmap.values()               # 所有值
hashmap.items()                # 所有键值对
len(hashmap)                   # 元素个数
```

## 1.2 哈希函数

### 1.2.1 哈希函数的作用与要求

**作用**：将任意类型的键（整数、字符串、元组等）映射为整数，再通过取模运算映射到数组索引。

**理想哈希函数的要求**：

1. **确定性**：相同的键必须产生相同的哈希值
2. **均匀性**：哈希值应尽可能均匀分布，减少冲突
3. **高效计算**：计算速度快
4. **雪崩效应**：键的微小变化应导致哈希值的巨大变化

**映射过程**：

```
key → hash(key) → h → h % table_size → index
```

### 1.2.2 常见哈希函数设计
**参数说明：**
- `table_size`: 表格大小

**1. 直接取模法（整数键）**

```python
def hash_int(key, table_size):
    return key % table_size
```

**2. 字符串哈希（多项式滚动哈希）**

将字符串视为多项式：`s[0]*p^(n-1) + s[1]*p^(n-2) + ... + s[n-1]`
对于下列代码来说，其中 `s[n]` 为字符的asc码，`p` 为base

```python
def hash_string(s, table_size, base=31, mod=10**9 + 7):
    """
    多项式滚动哈希
    base: 基数，通常取质数（如 31, 37, 101）
    mod: 大质数，防止溢出
    """
    h = 0
    for char in s:
        h = (h * base + ord(char)) % mod
    return h % table_size

# 示例
print(hash_string("hello", 100))  # 输出: 某个索引值
print(hash_string("world", 100))
```

**3. 通用哈希族（Universal Hashing）**

使用随机化的哈希函数族，理论上保证冲突概率低。实际中较少手动实现，依赖标准库。

### 1.2.3 Python 内置 hash() 函数

Python 提供内置的 `hash()` 函数，用于可哈希（不可变）对象：

```python
# 可哈希对象
print(hash(42))              # 整数
print(hash(3.14))            # 浮点数
print(hash("hello"))         # 字符串
print(hash((1, 2, 3)))       # 元组（元素也必须可哈希）
print(hash(True))            # 布尔值

# 不可哈希对象（会报错）
# hash([1, 2, 3])           # 列表：TypeError
# hash({"a": 1})            # 字典：TypeError
# hash({1, 2, 3})           # 集合：TypeError
```

**字典内部使用**：

```python
# Python 字典内部工作流程（简化）
key = "apple"
h = hash(key)           # 1. 计算哈希值
index = h % table_size  # 2. 映射到索引
# 3. 存储到 array[index]
```

> **注意**：Python 的 hash() 在每次运行时可能返回不同的值（出于安全考虑），但在同一次运行中对相同对象返回相同值。

## 1.3 冲突处理

### 1.3.1 冲突产生的原因

**冲突（Collision）**：不同的键被哈希函数映射到相同的数组索引。

```
hash("apple") % 10 = 2
hash("grape") % 10 = 2  ← 冲突！
```

**为什么冲突不可避免**？

- 键的可能取值远大于数组大小
- 根据鸽巢原理（Pigeonhole Principle），必然存在冲突
- 好的哈希函数只能**减少**冲突，不能**消除**冲突

### 1.3.2 链地址法（Chaining）
>每个数组位置存储一个链表，冲突的元素追加到链表中。
>用python中的表述，则是每个位置变成一个数组，存储的元素是一个个元组。这样哈希表永远不会满，但是需要额外的指针空间

**图示**：

```
数组索引    链表
  [0]   →  ("apple", "水果") → ("apricot", "杏") → NULL
  [1]   →  NULL
  [2]   →  ("banana", "香蕉") → NULL
  [3]   →  ("cherry", "樱桃") → ("cranberry", "蔓越莓") → NULL
  ...
```

**操作示例**：

```python
class HashTableChaining:
    def __init__(self, size=10):
        self.size = size
        self.table = [[] for _ in range(size)]  # 每个位置是空列表
    
    def _hash(self, key):
        return hash(key) % self.size
    
    def insert(self, key, value):
        """插入或更新键值对"""
        index = self._hash(key)
        bucket = self.table[index]
        
        # 查找是否已存在
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)  # 更新
                return
        
        # 不存在则追加
        bucket.append((key, value))
    
    def get(self, key, default=None):
        """查找键对应的值"""
        index = self._hash(key)
        bucket = self.table[index]
        
        for k, v in bucket:
            if k == key:
                return v
        
        return default  # 未找到
    
    def delete(self, key):
        """删除键值对"""
        index = self._hash(key)
        bucket = self.table[index]
        
        for i, (k, v) in enumerate(bucket):
            if k == key:
                del bucket[i]
                return True
        
        return False  # 未找到
```

> **注意**：Python 的 `dict` 与 `set` **并不使用链地址法**，而是属于开放寻址法（见 1.3.3 与 1.3.5）。使用拉链法的典型实现是 Java 的 `HashMap`（Java 8 起链表过长时转为红黑树）和 Go 的 `map`。

### 1.3.3 开放寻址法（Open Addressing）

**核心思想**：发生冲突时，按照某种探测序列寻找下一个空位。

**常见探测方式**：

1. **线性探测（Linear Probing）**：依次检查下一个位置
   ```
   index = (hash(key) + i) % table_size,  i = 0, 1, 2, ...
   ```

2. **二次探测（Quadratic Probing）**：跳跃式探测
   ```
   index = (hash(key) + i²) % table_size,  i = 0, 1, 2, ...
   ```

3. **双重哈希（Double Hashing）**：使用第二个哈希函数
   ```
   index = (hash1(key) + i * hash2(key)) % table_size
   ```

**图示（线性探测）**：

```
插入 "apple" → hash = 2
  [0]: 空
  [1]: 空
  [2]: ("apple", "水果")  ← 插入位置
  [3]: 空
  ...

插入 "grape" → hash = 2（冲突！）
  [0]: 空
  [1]: 空
  [2]: ("apple", "水果")  ← 被占用
  [3]: ("grape", "葡萄")  ← 探测到空位，插入这里
  ...

插入 "peach" → hash = 2（冲突！）
  [0]: 空
  [1]: 空
  [2]: ("apple", "水果")  ← 被占用
  [3]: ("grape", "葡萄")  ← 被占用
  [4]: ("peach", "桃子")  ← 探测到空位，插入这里
  ...
```

**操作示例**：

```python
class HashTableOpenAddressing:
    def __init__(self, size=10):
        self.size = size
        self.table = [None] * size  # None 表示空位
        self.count = 0  # 已存储元素数
    
    def _hash(self, key):
        return hash(key) % self.size
    
    def insert(self, key, value):
        """线性探测插入"""
        if self.count >= self.size * 0.7:  # 负载因子超过 0.7 时扩容
            self._resize()
        
        index = self._hash(key)
        
        # 线性探测寻找空位或相同键
        for i in range(self.size):
            probe_index = (index + i) % self.size
            
            if self.table[probe_index] is None:
                # 找到空位，插入
                self.table[probe_index] = (key, value)
                self.count += 1
                return
            
            if self.table[probe_index][0] == key:
                # 键已存在，更新
                self.table[probe_index] = (key, value)
                return
        
        raise Exception("哈希表已满")
    
    def get(self, key, default=None):
        """线性探测查找"""
        index = self._hash(key)
        
        for i in range(self.size):
            probe_index = (index + i) % self.size
            
            if self.table[probe_index] is None:
                return default  # 遇到空位，说明键不存在
            
            if self.table[probe_index][0] == key:
                return self.table[probe_index][1]
        
        return default
    
    def delete(self, key):
        """删除（需要特殊处理）"""
        index = self._hash(key)
        
        for i in range(self.size):
            probe_index = (index + i) % self.size
            
            if self.table[probe_index] is None:
                return False  # 未找到
            
            if self.table[probe_index][0] == key:
                # 标记为"已删除"而非 None
                # 否则会影响后续查找
                self.table[probe_index] = ("__DELETED__", None)
                self.count -= 1
                return True
        
        return False
```

**优点**：
- 不需要额外空间（无链表开销）
- 缓存友好（数据连续存储）

**缺点**：
- 容易产生聚集（Clustering）现象
- 删除操作复杂（需要标记而非真正删除）
- 表容量有限，负载因子不能太高

> 以上三种探测方式都是**教学模型**。CPython 在开放寻址的框架内另有一套实现，见 1.3.5。

### 1.3.4 负载因子与冲突概率

**负载因子（Load Factor）**：

```
α = 元素个数 / 表大小
```

- **α 越大**：冲突概率越高，性能下降
- **α 越小**：冲突概率低，但浪费空间

**经验值**：
- 链地址法：α 可以较大（如 2.0），性能仍可接受
- 开放寻址法：α 通常保持在 0.5 ~ 0.7 以下

**扩容策略**：当 α 超过阈值时，重新哈希（Rehashing）：
1. 创建更大的新表（通常 2 倍大小）
2. 将所有元素重新插入新表
3. 替换旧表

### 1.3.5 Python dict 的实际冲突处理（CPython 实现）

**结论**：CPython 的 `dict`/`set` 采用**开放寻址法**，但既不是线性探测也不是标准二次探测，而是自研的**扰动探测（Perturb Probing）**，并配合**紧凑布局（Compact Layout）**。

> 1.3.2 的链地址法与 1.3.3 的三种探测方式都是通用教学模型；Python 只取"开放寻址"这一大类，具体机制与教科书不同。

**1. 紧凑布局（Python 3.6+）**

`dict` 内部不是单个槽位数组，而是两个数组配合：

| 数组 | 内容 | 特点 |
|------|------|------|
| `dk_indices`（索引表） | `indices[i] = 条目下标` | 稀疏，只存整数（按表大小取 1/2/4/8 字节） |
| `dk_entries`（条目表） | `(hash, key, value)` 三元组 | **稠密**，按插入顺序依次追加 |

关键点：**哈希与探测只作用于 `indices` 表**。发生冲突时数据并不"挪位"，而是顺序追加到 `entries` 末尾，再把它在 `entries` 中的下标写进探测到的空槽。

这正是 Python 3.6 起 `dict` 遍历时表现为按插入顺序、3.7 起正式保证有序的原因。

**2. 探测公式：扰动探测**

表长恒为 2 的幂，因此取模退化为按位与：

```c
i = hash & mask;            // 首次探测，mask = 表长 - 1
perturb = hash;
while (槽位非空) {
    perturb >>= 5;          // PERTURB_SHIFT = 5
    i = (5 * i + perturb + 1) & mask;
}
```

两部分各司其职：

- **`j = 5j + 1 (mod 2^i)`**：该递推在 2^i 步内恰好遍历所有槽位各一次，保证表未满时一定能找到空位
- **`perturb`**：把哈希值的高位信息逐步"喂"进低位，使不同哈希值的探测序列彼此分离，避免一次聚集（Primary Clustering），同时不必引入第二个哈希函数

**手工演算示例**（表长 8，`mask = 7`，哈希值为 21）：

```
i0 = 21 & 7 = 5
perturb = 21 >> 5 = 0
i1 = (5×5 + 0 + 1) & 7 = 26 & 7 = 2
i2 = (5×2 + 0 + 1) & 7 = 11 & 7 = 3
i3 = (5×3 + 0 + 1) & 7 = 16 & 7 = 0
i4 =   5×0 + 1        =  1
i5 =   5×1 + 1        =  6
i6 = (5×6 + 1) & 7 = 31 & 7 = 7
i7 = (5×7 + 1) & 7 = 36 & 7 = 4
```

探测序列为 `5 → 2 → 3 → 0 → 1 → 6 → 7 → 4`，8 个槽位恰好各访问一次。

**3. 键相等判定：三级过滤**

每个条目保存了**完整的哈希值**，因此比较是分层的：

| 顺序 | 判据 | 代价 |
|------|------|------|
| 1 | `条目.hash == 待查hash` | 一次整数比较 |
| 2 | `条目.key is 待查key` | 指针比较（同一对象直接命中） |
| 3 | `条目.key == 待查key` | 调用 `__eq__` |

> **重要推论**：哈希值不同的键**永远不会调用 `__eq__`**，只有哈希碰撞时才会付这个代价。因此 `__eq__` 的实现速度会直接影响字典性能。

**4. 删除：墓碑标记**

开放寻址不能真正清空槽位（会截断后续元素的探测链），CPython 将索引表的槽位置为 `DKIX_DUMMY = -2`（空位为 `DKIX_EMPTY = -1`）。这与 1.3.3 中用 `("__DELETED__", None)` 占位是同一思路，只是改用整数标记。

**5. 扩容：负载因子 2/3**

阈值条件为 `used * 3 >= size * 2`，即 **α ≈ 2/3**，可用槽位数 = `size * 2 // 3`；新表大小 ≈ `used * 3` 向上取到 2 的幂。

实测 `sys.getsizeof` 的扩容轨迹（Python 3.12）：

```
    0 项 →   64 字节   空字典
    1 项 →  224 字节   分配表长 8，可用 5 个
    6 项 →  352 字节   ← 第 6 个触发，扩容至表长 16（可用 10 个）
   11 项 →  632 字节   ← 第 11 个触发，扩容至表长 32（可用 21 个）
   22 项 → 1168 字节   ← 第 22 个触发，扩容至表长 64（可用 42 个）
```

扩容时**只重建 `indices` 索引表**，`entries` 数组按原顺序整体拷贝。所以扩容不会打乱插入顺序，单次插入的分摊代价仍为 O(1)（见 1.4.2）。

**6. 哈希值本身**

- 字符串/字节串使用 **SipHash**（PEP 456），并配合环境变量 `PYTHONHASHSEED` **每次进程随机化**，防止攻击者构造大量同哈希键把 O(1) 退化为 O(n)（哈希碰撞拒绝服务攻击）
- `hash(-1) == -2`：`-1` 在 C 层被保留为错误哨兵，故整数 `-1` 的哈希值被改写成 `-2`

```python
# 同一次运行内哈希值稳定，跨进程不同
print(hash("abc"))   # 3798513404396659057
print(hash("abc"))   # -5645706281510566326  （另一次运行）
print(hash(-1))      # -2
```

**7. 与通用模型的对照**

| 机制 | 教科书模型 | CPython `dict` |
|------|-----------|----------------|
| 冲突处理 | 链地址法 / 开放寻址法 | 开放寻址法 |
| 探测方式 | 线性、二次、双重哈希 | **扰动探测（perturb）** |
| 空位判定 | `None` | `DKIX_EMPTY = -1` |
| 删除 | 真删除 / 标记 | **墓碑 `DKIX_DUMMY = -2`** |
| 负载因子阈值 | 0.5 ~ 0.7 | **2/3** |
| 扩容 | 重新哈希全部元素 | 重建索引表，条目数组整体拷贝 |

## 1.4 时间复杂度分析

### 1.4.1 理想情况 vs 最坏情况

| 操作 | 平均情况 | 最坏情况 | 说明 |
|------|---------|---------|------|
| 插入 | O(1) | O(n) | 最坏：所有元素冲突，退化为链表 |
| 查找 | O(1) | O(n) | 最坏：同上 |
| 删除 | O(1) | O(n) | 最坏：同上 |

**理想情况**：
- 哈希函数分布均匀
- 负载因子适中
- 冲突少，链表短或探测步数少

**最坏情况**：
- 所有键哈希到同一位置
- 退化为链表（链地址法）或线性扫描（开放寻址法）

### 1.4.2 平均性能与负载因子

**链地址法**：
- 平均链表长度 = α
- 查找时间 ≈ O(1 + α)
- 当 α = O(1) 时，查找时间 = O(1)

**开放寻址法（线性探测）**：
- 平均探测次数 ≈ 1 / (1 - α)
- 当 α → 1 时，性能急剧下降
- α = 0.5 时，平均探测约 2 次

**扩容操作**：
- 单次扩容：O(n)
- 分摊成本（Amortized Cost）：O(1)
