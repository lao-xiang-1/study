# 1 哈希表（Hash Table）

哈希表是一种高效的数据结构，通过哈希函数将键（key）映射到数组的特定位置，从而实现平均 O(1) 时间复杂度的查找、插入和删除操作。

---

## 1.1 什么是哈希表

### 1.1.1 定义与核心思想

**哈希表** = **数组** + **哈希函数**

核心思想：通过哈希函数将任意类型的键转换为数组索引，直接定位到存储位置，避免遍历。

**工作流程**：

```
key → hash(key) → index → array[index] = value
```

**图示**：

```
┌─────────────────────────────────────┐
│           哈希表 (Hash Table)        │
├─────────────────────────────────────┤
│                                     │
│  key: "apple"                       │
│   ↓                                 │
│  hash("apple") → 计算哈希值 7        │
│   ↓                                 │
│  7 % 表大小 → index = 2             │
│   ↓                                 │
│  array[2] = "水果"                   │
│                                     │
├─────────────────────────────────────┤
│  数组存储:                           │
│  [0]: ...                           │
│  [1]: ...                           │
│  [2]: "水果"  ← 存储位置             │
│  [3]: ...                           │
│  ...                                │
└─────────────────────────────────────┘
```

### 1.1.2 为什么需要哈希表

**与数组、链表的对比**：

| 操作 | 数组（有序） | 链表 | 二叉搜索树 | 哈希表 |
|------|-------------|------|-----------|--------|
| 查找 | O(log n) | O(n) | O(log n) | **O(1) 平均** |
| 插入 | O(n) | O(1)* | O(log n) | **O(1) 平均** |
| 删除 | O(n) | O(1)* | O(log n) | **O(1) 平均** |

> *链表插入/删除需要先找到位置 O(n)，找到后操作本身 O(1)

**关键点**：
- 哈希表在**平均情况**下提供 O(1) 操作，远优于其他数据结构
- 但**最坏情况**可能退化为 O(n)
- 适用于需要频繁查找、去重、计数的场景

### 1.1.3 基础 API

**Python 中的 dict 就是哈希表**：

```python
# 插入/更新
hashmap = {}
hashmap["name"] = "Alice"      # hashmap[key] = value
hashmap.update({"age": 25})    # 批量更新

# 查找
name = hashmap["name"]         # 直接访问，O(1)
age = hashmap.get("age", 0)    # 安全访问，不存在返回默认值

# 删除
del hashmap["age"]             # 删除指定键值对
age = hashmap.pop("age", 0)    # 删除并返回值

# 其他常用操作
"age" in hashmap               # 判断键是否存在，O(1)
hashmap.keys()                 # 所有键
hashmap.values()               # 所有值
hashmap.items()                # 所有键值对
len(hashmap)                   # 元素个数
```

## 1.2 哈希函数

### 1.2.1 哈希函数的作用与要求

**作用**：将任意类型的键（整数、字符串、元组等）映射为整数，再通过取模运算映射到数组索引。

**理想哈希函数的要求**：

1. **确定性**：相同的键必须产生相同的哈希值
2. **均匀性**：哈希值应尽可能均匀分布，减少冲突
3. **高效计算**：计算速度快
4. **雪崩效应**：键的微小变化应导致哈希值的巨大变化

**映射过程**：

```
key → hash(key) → h → h % table_size → index
```

### 1.2.2 常见哈希函数设计

**1. 直接取模法（整数键）**

```python
def hash_int(key, table_size):
    return key % table_size
```

**2. 字符串哈希（多项式滚动哈希）**

将字符串视为多项式：`s[0]*p^(n-1) + s[1]*p^(n-2) + ... + s[n-1]`

```python
def hash_string(s, table_size, base=31, mod=10**9 + 7):
    """
    多项式滚动哈希
    base: 基数，通常取质数（如 31, 37, 101）
    mod: 大质数，防止溢出
    """
    h = 0
    for char in s:
        h = (h * base + ord(char)) % mod
    return h % table_size

# 示例
print(hash_string("hello", 100))  # 输出: 某个索引值
print(hash_string("world", 100))
```

**3. 通用哈希族（Universal Hashing）**

使用随机化的哈希函数族，理论上保证冲突概率低。实际中较少手动实现，依赖标准库。

### 1.2.3 Python 内置 hash() 函数

Python 提供内置的 `hash()` 函数，用于可哈希（不可变）对象：

```python
# 可哈希对象
print(hash(42))              # 整数
print(hash(3.14))            # 浮点数
print(hash("hello"))         # 字符串
print(hash((1, 2, 3)))       # 元组（元素也必须可哈希）
print(hash(True))            # 布尔值

# 不可哈希对象（会报错）
# hash([1, 2, 3])           # 列表：TypeError
# hash({"a": 1})            # 字典：TypeError
# hash({1, 2, 3})           # 集合：TypeError
```

**字典内部使用**：

```python
# Python 字典内部工作流程（简化）
key = "apple"
h = hash(key)           # 1. 计算哈希值
index = h % table_size  # 2. 映射到索引
# 3. 存储到 array[index]
```

> **注意**：Python 的 hash() 在每次运行时可能返回不同的值（出于安全考虑），但在同一次运行中对相同对象返回相同值。

## 1.3 冲突处理

### 1.3.1 冲突产生的原因

**冲突（Collision）**：不同的键被哈希函数映射到相同的数组索引。

```
hash("apple") % 10 = 2
hash("grape") % 10 = 2  ← 冲突！
```

**为什么冲突不可避免**？

- 键的可能取值远大于数组大小
- 根据鸽巢原理（Pigeonhole Principle），必然存在冲突
- 好的哈希函数只能**减少**冲突，不能**消除**冲突

### 1.3.2 链地址法（Chaining）

**核心思想**：每个数组位置存储一个链表，冲突的元素追加到链表中。

**图示**：

```
数组索引    链表
  [0]   →  ("apple", "水果") → ("apricot", "杏") → NULL
  [1]   →  NULL
  [2]   →  ("banana", "香蕉") → NULL
  [3]   →  ("cherry", "樱桃") → ("cranberry", "蔓越莓") → NULL
  ...
```

**操作示例**：

```python
class HashTableChaining:
    def __init__(self, size=10):
        self.size = size
        self.table = [[] for _ in range(size)]  # 每个位置是空列表
    
    def _hash(self, key):
        return hash(key) % self.size
    
    def insert(self, key, value):
        """插入或更新键值对"""
        index = self._hash(key)
        bucket = self.table[index]
        
        # 查找是否已存在
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)  # 更新
                return
        
        # 不存在则追加
        bucket.append((key, value))
    
    def get(self, key, default=None):
        """查找键对应的值"""
        index = self._hash(key)
        bucket = self.table[index]
        
        for k, v in bucket:
            if k == key:
                return v
        
        return default  # 未找到
    
    def delete(self, key):
        """删除键值对"""
        index = self._hash(key)
        bucket = self.table[index]
        
        for i, (k, v) in enumerate(bucket):
            if k == key:
                del bucket[i]
                return True
        
        return False  # 未找到
```

**优点**：
- 实现简单直观
- 表永远不会满（链表可以无限增长）

**缺点**：
- 需要额外的指针空间
- 链表遍历不如数组快（缓存不友好）

### 1.3.3 开放寻址法（Open Addressing）

**核心思想**：发生冲突时，按照某种探测序列寻找下一个空位。

**常见探测方式**：

1. **线性探测（Linear Probing）**：依次检查下一个位置
   ```
   index = (hash(key) + i) % table_size,  i = 0, 1, 2, ...
   ```

2. **二次探测（Quadratic Probing）**：跳跃式探测
   ```
   index = (hash(key) + i²) % table_size,  i = 0, 1, 2, ...
   ```

3. **双重哈希（Double Hashing）**：使用第二个哈希函数
   ```
   index = (hash1(key) + i * hash2(key)) % table_size
   ```

**图示（线性探测）**：

```
插入 "apple" → hash = 2
  [0]: 空
  [1]: 空
  [2]: ("apple", "水果")  ← 插入位置
  [3]: 空
  ...

插入 "grape" → hash = 2（冲突！）
  [0]: 空
  [1]: 空
  [2]: ("apple", "水果")  ← 被占用
  [3]: ("grape", "葡萄")  ← 探测到空位，插入这里
  ...

插入 "peach" → hash = 2（冲突！）
  [0]: 空
  [1]: 空
  [2]: ("apple", "水果")  ← 被占用
  [3]: ("grape", "葡萄")  ← 被占用
  [4]: ("peach", "桃子")  ← 探测到空位，插入这里
  ...
```

**操作示例**：

```python
class HashTableOpenAddressing:
    def __init__(self, size=10):
        self.size = size
        self.table = [None] * size  # None 表示空位
        self.count = 0  # 已存储元素数
    
    def _hash(self, key):
        return hash(key) % self.size
    
    def insert(self, key, value):
        """线性探测插入"""
        if self.count >= self.size * 0.7:  # 负载因子超过 0.7 时扩容
            self._resize()
        
        index = self._hash(key)
        
        # 线性探测寻找空位或相同键
        for i in range(self.size):
            probe_index = (index + i) % self.size
            
            if self.table[probe_index] is None:
                # 找到空位，插入
                self.table[probe_index] = (key, value)
                self.count += 1
                return
            
            if self.table[probe_index][0] == key:
                # 键已存在，更新
                self.table[probe_index] = (key, value)
                return
        
        raise Exception("哈希表已满")
    
    def get(self, key, default=None):
        """线性探测查找"""
        index = self._hash(key)
        
        for i in range(self.size):
            probe_index = (index + i) % self.size
            
            if self.table[probe_index] is None:
                return default  # 遇到空位，说明键不存在
            
            if self.table[probe_index][0] == key:
                return self.table[probe_index][1]
        
        return default
    
    def delete(self, key):
        """删除（需要特殊处理）"""
        index = self._hash(key)
        
        for i in range(self.size):
            probe_index = (index + i) % self.size
            
            if self.table[probe_index] is None:
                return False  # 未找到
            
            if self.table[probe_index][0] == key:
                # 标记为"已删除"而非 None
                # 否则会影响后续查找
                self.table[probe_index] = ("__DELETED__", None)
                self.count -= 1
                return True
        
        return False
```

**优点**：
- 不需要额外空间（无链表开销）
- 缓存友好（数据连续存储）

**缺点**：
- 容易产生聚集（Clustering）现象
- 删除操作复杂（需要标记而非真正删除）
- 表容量有限，负载因子不能太高

### 1.3.4 负载因子与冲突概率

**负载因子（Load Factor）**：

```
α = 元素个数 / 表大小
```

- **α 越大**：冲突概率越高，性能下降
- **α 越小**：冲突概率低，但浪费空间

**经验值**：
- 链地址法：α 可以较大（如 2.0），性能仍可接受
- 开放寻址法：α 通常保持在 0.5 ~ 0.7 以下

**扩容策略**：当 α 超过阈值时，重新哈希（Rehashing）：
1. 创建更大的新表（通常 2 倍大小）
2. 将所有元素重新插入新表
3. 替换旧表

## 1.4 时间复杂度分析

### 1.4.1 理想情况 vs 最坏情况

| 操作 | 平均情况 | 最坏情况 | 说明 |
|------|---------|---------|------|
| 插入 | O(1) | O(n) | 最坏：所有元素冲突，退化为链表 |
| 查找 | O(1) | O(n) | 最坏：同上 |
| 删除 | O(1) | O(n) | 最坏：同上 |

**理想情况**：
- 哈希函数分布均匀
- 负载因子适中
- 冲突少，链表短或探测步数少

**最坏情况**：
- 所有键哈希到同一位置
- 退化为链表（链地址法）或线性扫描（开放寻址法）

### 1.4.2 平均性能与负载因子

**链地址法**：
- 平均链表长度 = α
- 查找时间 ≈ O(1 + α)
- 当 α = O(1) 时，查找时间 = O(1)

**开放寻址法（线性探测）**：
- 平均探测次数 ≈ 1 / (1 - α)
- 当 α → 1 时，性能急剧下降
- α = 0.5 时，平均探测约 2 次

**扩容操作**：
- 单次扩容：O(n)
- 分摊成本（Amortized Cost）：O(1)

## 1.5 Python 实现

### 1.5.1 基于链地址法的简单哈希表

完整实现（含动态扩容）：

```python
class HashTable:
    def __init__(self, capacity=8):
        self.capacity = capacity  # 表容量
        self.size = 0             # 元素个数
        self.table = [[] for _ in range(capacity)]
        self.load_factor_threshold = 0.75  # 负载因子阈值
    
    def _hash(self, key):
        """计算哈希索引"""
        return hash(key) % self.capacity
    
    def insert(self, key, value):
        """插入键值对，支持动态扩容"""
        # 检查是否需要扩容
        if self.size / self.capacity >= self.load_factor_threshold:
            self._resize()
        
        index = self._hash(key)
        bucket = self.table[index]
        
        # 查找是否已存在
        for i, (k, v) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)  # 更新
                return
        
        # 不存在则追加
        bucket.append((key, value))
        self.size += 1
    
    def get(self, key, default=None):
        """查找"""
        index = self._hash(key)
        for k, v in self.table[index]:
            if k == key:
                return v
        return default
    
    def delete(self, key):
        """删除"""
        index = self._hash(key)
        bucket = self.table[index]
        
        for i, (k, v) in enumerate(bucket):
            if k == key:
                del bucket[i]
                self.size -= 1
                return True
        return False
    
    def _resize(self):
        """扩容：容量翻倍，重新哈希所有元素"""
        old_table = self.table
        self.capacity *= 2
        self.table = [[] for _ in range(self.capacity)]
        self.size = 0
        
        # 重新插入所有元素
        for bucket in old_table:
            for key, value in bucket:
                self.insert(key, value)
    
    def __setitem__(self, key, value):
        """支持 hashmap[key] = value 语法"""
        self.insert(key, value)
    
    def __getitem__(self, key):
        """支持 hashmap[key] 语法"""
        result = self.get(key)
        if result is None:
            raise KeyError(key)
        return result
    
    def __delitem__(self, key):
        """支持 del hashmap[key] 语法"""
        if not self.delete(key):
            raise KeyError(key)
    
    def __contains__(self, key):
        """支持 key in hashmap 语法"""
        return self.get(key) is not None
    
    def __len__(self):
        """支持 len(hashmap) 语法"""
        return self.size
```

**使用示例**：

```python
# 创建哈希表
ht = HashTable()

# 插入
ht["name"] = "Alice"
ht["age"] = 25
ht.insert("city", "Beijing")

# 查找
print(ht["name"])           # Alice
print(ht.get("gender", "unknown"))  # unknown

# 更新
ht["age"] = 26

# 删除
del ht["city"]

# 判断存在
print("age" in ht)         # True
print("city" in ht)        # False

# 长度
print(len(ht))             # 2
```

### 1.5.2 动态扩容（Rehashing）

**扩容时机**：当负载因子超过阈值（如 0.75）时

**扩容过程**：
1. 分配新表（容量翻倍）
2. 遍历旧表所有元素
3. 重新计算哈希值并插入新表
4. 释放旧表

**代码**（见上文 `_resize` 方法）

**性能分析**：
- 单次扩容：O(n)
- 分摊成本：每次插入 O(1)
