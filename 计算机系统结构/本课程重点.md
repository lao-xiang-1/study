# 计算机系统结构 · 重点提炼

## 0. 全书主线

一句话：**在软硬件界面上，用「重叠、重复、共享」三条途径挖掘并行性；而一切性能判断最终都折算成 Amdahl 定律与 CPU 性能公式。**

由此贯穿六章的四把尺子：

| 尺子 | 公式 / 内容 | 用在哪里 |
| --- | --- | --- |
| Amdahl 定律 | $S=\dfrac{1}{(1-f)+f/k}$，上限 $\dfrac{1}{1-f}$ | 第1章定量原理、第3章小改进的局限、第6章 I/O 性能 |
| CPU 性能公式 | $CPU时间 = IC \times CPI \times 时钟周期时间$ | 第1、4章；第5章把它扩展成含访存停顿的形式 |
| 局部性原理 | 时间局部性 + 空间局部性 | 第1章的定量原理 → 第5章整个存储层次 |
| 以经常性事件为重点 | — | 第2章指令频度统计 → CISC/RISC 之争的起点 |

**关键洞察**：性能 = 时间。任何"提高 X 倍"的说法，都要追问一句「X 原来占多少时间」。

## 1. 基本概念

### 三个必须分清的概念

| 概念 | 是什么 | 决定 |
| --- | --- | --- |
| **计算机系统结构** | 软硬件界面，即机器语言程序员所看到的属性（概念性结构与功能特性） | 是否**兼容** |
| **计算机组成** | 系统结构的**逻辑实现** | 是否**高效** |
| **计算机实现** | 组成的**物理实现** | 是否**便宜** |

**一种结构可以有多种组成；一种组成可以有多种实现。** 系列机 = 相同结构 + 不同组成和实现。

**透明性**：本来存在、但从某个角度看又好像不存在。**虚拟机**：由软件实现的机器。

### 硬件与软件的分工、以及软件可移植性

- 指令集结构设计要回答"哪些功能交给硬件"。权衡三维度：**速度、成本、灵活性**。
- 语言实现的两种技术：**翻译**（编译后执行，快但占空间）与**解释**（边译边执行，慢但省空间）。
- 可移植性三条路：系列机、模拟与仿真、统一高级语言。
  - **模拟**：用**解释**实现另一台机器的指令集 → 慢
  - **仿真**：用**微程序**实现 → 快，但只能用于结构差距不大的机器之间
- 四种兼容方向中，**向后兼容是系列机的根本特征**。

### 并行性（全书的主题）

- 从**数据**角度（低→高）：字串位串（无并行）→ 字串位并（开始有并行）→ 字并位串 → 全并行
- 从**程序**角度（低→高）：指令内部 → 指令级 → 线程级 → 任务级 → 作业级
- **三条技术途径**：时间重叠（引入**时间**因素）、资源重复（引入**空间**因素）、资源共享（**软件**方法）
- 单机性能发展主要靠**时间重叠**，其基础是**部件功能专用化**；多机系统看**耦合度**（紧密 = 共享主存；松散 = 共享外存，在文件/数据集一级交互）

### 分类法

- **Flynn**：按指令流/数据流的多倍性 → SISD、SIMD、MIMD（**MISD 罕见、实际不存在**）
- **冯氏**：按**最大并行度** $m \times n$（字数 × 字宽）

## 2. 指令集结构

### 分类依据

区别不同指令集结构的主要因素是 **CPU 中用来存储操作数的存储单元类型** → 堆栈 / 累加器 / **通用寄存器**。

通用寄存器结构再按「ALU 指令中存储器操作数的个数、操作数的最多个数」记为 $(m,n)$：

- **RR（0,3）** = load-store 结构，只有 load/store 能访存 → 指令条数多，但定长、规整、适合流水（MIPS、ARM…）
- **RM（1,2）** = ALU 指令可直接带一个存储器操作数 → 目标代码紧凑，但执行时间因操作数来源不同而差异大（80x86…）
- MCC（2,2）/（3,3）MM 型 → 代码最紧凑，但访存频繁使存储器成瓶颈，现已不用

### 寻址方式

核心问题：如何确定要访问的数据的地址。能写出各方式的 `Regs[...]` / `Mem[...]` 含义即可。

- **统计结论**（VAX 上 gcc/Spice/Tex）：**立即数寻址与偏移寻址使用频度最高**；约 1/4 的 load 与 ALU 指令用立即数；立即数字段至少设 8～16 位。
- **权衡**：多种寻址方式能**显著减少指令条数**，但会增加实现复杂度与 CPI。

### CISC 与 RISC —— 本章的灵魂

**CISC 的出发点**：强化指令功能、减少程序指令条数。三个方向：面向目标程序、面向高级语言的优化实现、面向操作系统的优化实现。

**致命统计**（Patterson 等人自 1979 年起）：只有 **20% 的指令使用频度高，却占 80% 的运行时间**；而**使用频度高的恰恰是最简单的指令**。

**CISC 的后果**：控制器硬件复杂、占芯片面积大；复杂指令 CPI 大，用它们反而可能拖慢整个程序；规整性差，不利于流水。
> 记住这条因果链比背对照表有用：**频度统计 → 简单指令才是热点 → 简单指令才适合流水 → 把复杂度从硬件推给编译器。**

**RISC 的答案（设计原则）**：指令少而简单（只选取使用频度很高的指令）；格式简单统一、指令字长 32 或 64 位、寻址方式少；指令在**单个机器周期**内完成；**只有 load/store 访存**；大多数指令用**硬连逻辑**实现；**强调优化编译器**；充分利用流水技术。

### MIPS（MIPS64 的一个子集）

- 32 个 64 位通用寄存器（**R0 恒为 0**，可用来合成常数装入与寄存器传送）+ 32 个 64 位浮点寄存器 + 8 个特殊寄存器
- **所有指令都是 32 位，操作码占 6 位**；寻址方式编码进操作码；存储器按字节寻址、访问必须**边界对齐**

| 格式 | 字段（32 位） | 包含什么 |
| --- | --- | --- |
| **I** | `op`(6) \| `rs`(5) \| `rt`(5) \| `immediate`(16) | 所有 load/store、立即数指令、分支、寄存器跳转 |
| **R** | `op`(6) \| `rs`(5) \| `rt`(5) \| `rd`(5) \| `shamt`(5) \| `funct`(6) | ALU、专用寄存器读写、move |
| **J** | `op`(6) \| `target`(26) | 跳转、跳转并链接、自陷、异常返回 |

- 分支：目标 = PC + (16 位**带符号**偏移量 << 2)，范围 $(\text{PC}+4)\pm 2^{17}$
- 跳转：26 位偏移 << 2 替换 PC 低 28 位，范围 $(\text{PC}+4)\pm 2^{27}$
- 分支偏移量是**带符号**的；立即数与偏移量字段都是 **16 位**
- **R0 恒为 0** 的用法：装入常数（`DADDIU R1, R0, #100`）、寄存器间传送（`DADD R1, R0, R2`）
- 浮点指令后缀 **S / D** 表示单/双精度；浮点分支用 **BC1T / BC1F** 测试浮点状态寄存器中的位

## 3. 流水线技术

### 3.1 性能：三个指标其实是一个

| 指标 | 各段等时 | 最大（$n \gg k$） |
| --- | --- | --- |
| 吞吐率 | $TP = \dfrac{n}{(k+n-1)\Delta t}$ | $TP_{max} = \dfrac{1}{\Delta t}$ |
| 加速比 | $S = \dfrac{nk}{k+n-1}$ | $S_{max} = k$ |
| 效率 | $E = \dfrac{n}{k+n-1}$ | $E_{max} = 1$ |

**统摄关系：$E = TP \cdot \Delta t = \dfrac{S}{k}$**（$E = S/k$ 对各段不等时也成立；$E = TP\cdot\Delta t$ 只适用于各段等时）。从时空图看：效率就是 n 个任务占用的时空面积与 k 个段总时空面积之比。

- 各段不等时：设瓶颈段为 $\Delta t_j$，则 $TP_{max} = 1/\Delta t_j$，$TP = \dfrac{n}{\sum_{i=1}^{k}\Delta t_i + (n-1)\Delta t_j}$。
- **瓶颈段两条出路**：**细分瓶颈段**（增加段数，各段重新等时）vs **重复设置瓶颈段**（并行多份；控制逻辑复杂、硬件增加）。

### 3.2 相关与冲突 —— 全章的核心

**相关是程序固有的属性；冲突才是流水线的属性。** 同一次相关是否引发冲突、会停顿多久，取决于具体流水线。

| 相关（根源） | 对应冲突 | 解决手段 |
| --- | --- | --- |
| **数据相关**（真相关，**有传递性**） | 数据冲突 **RAW** | 定向（旁路/短路）、load 互锁插暂停、编译器指令调度 |
| **名相关**：反相关 / 输出相关 | **WAR** / **WAW** | 换名技术（寄存器换名；编译器静态或硬件动态实现） |
| **控制相关**（分支引起） | 控制冲突 | 尽早判分支与算目标、分支预测、延迟分支、分支取消 |
| — | 结构冲突（资源份数不够 / 部件未流水） | 插暂停（气泡）、分离指令与数据 Cache、部件流水化或重复设置 |

要点：

- **经典 5 段流水线（IF-ID-EX-MEM-WB）不会发生 WAR 和 WAW**（写只在 WB 段、读在 ID 段）。它们只在**乱序执行**时出现——这正是动态调度的动机。
- **定向技术**：把结果从产生的地方直接送到需要它的地方，不必等写回寄存器。**但 load 的结果无法定向**（数据在 MEM 段末才出来），必须插暂停，即 **load 互锁**。
- **冲突约定**：暂停某条指令时，其后流出的指令一起停，其前流出的继续流进。

### 3.3 控制冲突

5 段流水线中改变 PC 在 MEM 段完成 → **分支延迟 3 个时钟周期**。

- 量级感受：分支频度 30%、理想 CPI = 1 时，**实际 CPI = 1 + 0.3×3 = 1.9**。
- 两条改进思路：尽早判定分支是否成功、尽早算出目标地址。两者都提前到 **ID 段**完成 → **分支延迟降为 1 个周期**。
- **软件三法**（均为**静态**：处理方式在整个执行过程中不变）：
  1. **预测分支失败**——分支后的指令照常流水，猜错则把它们转为空操作；须保证猜错前不改变机器状态以便回退
  2. **预测分支成功**——前提是先知道目标地址、后知道成功与否；在前述 5 段流水线上**没有任何好处**
  3. **延迟分支**——逻辑上延长分支指令，**延迟槽中的指令无论分支成败都要执行**
- 延迟槽的三种调度：**从前调度**（任何情况都能用）、**从目标处调度**（仅分支成功时有效，可能需要复制指令、增大程序空间）、**从失败处调度**（仅分支失败时有效）。
- 分支延迟受两个限制：能进延迟槽的指令要满足条件；编译器预测分支方向的能力。

### 3.4 向量处理机

| 处理方式 | 数据相关 | 功能切换 | 对结构的要求 |
| --- | --- | --- | --- |
| **横向（水平，按行）** | N 次 | 2N 次 | 不适合并行处理，最差 |
| **纵向（垂直，按列）** | 1 次 | 1 次 | **存储器－存储器**结构 |
| **纵横（分组，组内纵向）** | 1 次/组 | 2 次/组 | **寄存器－寄存器**结构 |

**链接技术**：把有"先写后读"相关的两条向量指令的功能部件**直接串接**起来流水处理，不必等结果落回寄存器——**本质是把流水线的定向思想引入向量执行**。收益显著（例 3.3：串行 $3N+22$ 拍 → 并行+链接 $N+16$ 拍）。

链接成立条件（严格，常考）：

1. 无**向量寄存器（Vi）冲突**、无**功能部件冲突**；
2. 只有在前一条指令的**第一个结果元素送入结果寄存器的那一拍**才可以链接；
3. 当一条指令的两个源操作数分别来自两条先行指令时，这两条先行指令的**功能部件通过时间必须相等**；
4. 参与链接的向量**长度必须相等**。

**分段开采**：向量长度大于向量寄存器长度时，$K=\lfloor N/64 \rfloor$、$L=N \bmod 64$，先处理余数 L 个元素，再循环 K 次分段处理；由软硬件控制，**对程序员透明**。

**提高向量机性能四法**：多个功能部件并行、链接技术、分段开采、多处理机系统。

## 4. 指令级并行

### 4.1 动机与开销公式

$$CPI_{流水线} = CPI_{理想} + 停顿_{结构冲突} + 停顿_{数据冲突} + 停顿_{控制冲突}$$

程序平均每 **5～7 条指令**就有一个分支 → **循环级并行**是最常见、最基本的开发对象（最基本的开发技术是**循环展开**）。

**必须保持的只有两样：数据流 和 异常行为**（保持精确异常）。控制相关不是必须严格保持的属性——若能保持数据流与异常行为，就可以大胆地把失败分支中的指令调度到分支之前。

### 4.2 Tomasulo 算法（第一重点）

**要解决什么**：基本流水线要求指令按序流出和执行，一条受阻则后面全停。把 ID 再分为 **IS 流出（按序）** 与 **RO 读操作数（乱序）**，允许乱序执行；代价是引入 WAR/WAW 冲突与不精确异常。

**三条支柱**：

1. **保留站**——保存已流出、等待执行的指令（操作码、操作数、用于检测冲突的信息）。操作数已就绪就取进来；否则记下"哪个保留站会产生它"。**冲突检测和指令执行控制是分布的**，由各功能部件自己的保留站决定何时开始执行。
2. **寄存器换名**——流出时把寄存器号换成保留站标识，指令此后**不再与寄存器有关系**，从而**消除 WAR 与 WAW**；同时对目标寄存器预约，也消除 WAW。
3. **CDB（公共数据总线）**——所有功能部件的计算结果都送到 CDB，**广播**给所有需要它的地方，**不经过寄存器**。多流出时需多条 CDB。

**三段**：

- **流出**：从指令队列头部取指令；有空闲保留站才能流出（否则是结构冲突）
- **执行**：两个操作数都就绪才开始；load/store 还需成为缓冲队列的头部（先算有效地址，再放入缓冲器）
- **写结果**：结果上 CDB，所有等它的寄存器（Qi）和保留站（Qj/Qk）同时取走

**字段记忆要点**：`Qj/Qk` = 将产生源操作数的保留站号，**为 0 表示操作数已就绪在 `Vj`/`Vk` 中**（或不需要操作数）；**每个操作数 V 和 Q 只有一个有效**；`Busy`；`A` 仅 load/store 缓冲器有（先存立即数，算完存有效地址）；**load 的 `Vk` 用于保存偏移量**。`Qi` 寄存器状态表记录"哪个保留站将把结果写入该寄存器"。

> IBM 360/91 的背景说明了算法动机：只有 4 个双精度浮点寄存器（寄存器不够用、编译器难以调度），且访存与浮点计算时间都很长。

### 4.3 前瞻执行

**= Tomasulo + ROB**。对分支结果进行猜测并照着往下取、流出、执行，但**结果先写进 ROB，不写寄存器/存储器**；等到指令被"确认"后才真正写入。

**关键思想：允许指令乱序执行，但必须顺序确认。** 由此获得**精确异常**——这是它相对普通动态调度的最大收获。

- **ROB 四项字段**：指令类型、目标地址、数据值、就绪字段
- 换名改由 **ROB 的项编号**承担（取代保留站编号）
- 确认时按类型分别处理：普通指令写寄存器并出队；store 写存储器；**分支猜错则清空 ROB，从另一条路径重新执行**
- 主要缺点：**硬件太复杂**

### 4.4 分支预测

| 方法 | 机制 | 何时有用 / 效果 |
| --- | --- | --- |
| **BHT**（分支历史表 / 分支预测缓冲器） | 用 1 位或 2 位记录该分支最近一次或几次的执行情况 | **仅当"判定分支是否成功"比"确定分支目标地址"更慢时才有用**——5 段流水线上两者都在 ID 段完成，故**无收益**。2 位预测的性能已接近 n 位（n>2）；4K 的 BHT 准确率 82%~99% |
| **BTB**（分支目标缓冲器） | 以**分支指令的地址**为标识，存预测的分支目标地址 | 目标是**把分支开销降为 0**。延迟：命中且成功 0 拍；未命中且实际不成功 0 拍；其余情况 2 拍 |
| BTB 的变体 | 直接存放分支目标处的指令 | 可实现**分支折叠**，做到零延迟无条件分支，有时还能零延迟条件分支 |

**动态预测为何重要**：n 流出的处理机遇到分支的机会增加 n 倍；且 CPI 越小，控制停顿的相对影响越大（Amdahl）。

### 4.5 多流出：超标量 / VLIW / 超流水线

| | 超标量 | VLIW | 超流水线 |
| --- | --- | --- | --- |
| 每周期流出 | 不固定，依代码而定（有上限 n，称 n 流出） | 固定，构成一条长指令/指令包 | 一个时钟周期内**分时**流出 n 条（每隔 $1/n$ 周期一条） |
| 并行性表示 | 由**硬件**检测 | 指令**显式**表示（操作槽） | 细分流水段 |
| 调度 | 可静态可动态 | **全部由编译器静态完成** | — |
| 主要特点 | **对程序员透明**，旧代码也能运行 | 代码膨胀、**锁步机制**（一处停顿全机停）、机器代码不兼容 | 流水线级数多（R4000 为 8 级） |

两种多流出实现途径：在半个时钟周期里完成流出步骤；或设置一次能处理两条指令的逻辑电路。现代流出 4 条以上的处理机常常**两者都用**。

**多流出受三方面限制**：程序固有的 ILP、硬件实现困难、超标量与 VLIW 的技术固有缺陷。

### 4.6 循环展开与指令调度

思想：复制循环体、**寄存器换名**、调整操作数偏移量与循环控制，把相关指令拉开距离以消除空转。

注意六个方面：保证**正确性**（循环控制、偏移量修改）、注意**有效性**（循环体之间确实无关）、使用**不同的寄存器**、删除冗余测试与分支、注意**存储器相关**（不同迭代访存地址不同才可对调）、注意展开后可能带来**新的相关**。

## 5. 存储系统

### 5.1 母公式

$$\text{平均访存时间} = \text{命中时间} + \text{不命中率} \times \text{不命中开销}$$

整章的 17 种优化技术只是这个公式的三条天梯：8 种降不命中率、5 种降不命中开销、4 种降命中时间。

**关键张力**：大多数降不命中率的手段会**抬高命中时间或不命中开销**（增大块、增大容量、提高相联度都变慢），这正是必须权衡的原因。

CPU 时间扩展式（必会）：

$$\text{CPU时间} = IC \times (\text{CPI}_{execution} + 每条指令平均访存次数 \times 不命中率 \times 不命中开销) \times 时钟周期时间$$

### 5.2 映像与地址划分

| | 映像规则 | 块冲突 | 空间利用率 | 实现 |
| --- | --- | --- | --- | --- |
| **直接映像** | $j = i \bmod M$，唯一位置 | 最高 | 最低 | 最简单 |
| **组相联** | $k = i \bmod G$，**组内**任意位置 | 居中 | 居中 | 居中 |
| **全相联** | **任意**位置 | 最低 | 最高 | 最复杂 |

- 相联度 $n = M/G$：直接映像 $n=1$、全相联 $n=M$；**绝大多数机器 $n \le 4$**。
- **地址划分三件套**（必会算）：块内位移 $= \log_2(\text{块大小})$；索引 $= \log_2(\text{组数})$；标识 $=$ 地址位数 $-$ 索引位 $-$ 位移位。也可由 $\text{Cache 容量} = 2^{index} \times 相联度 \times 块大小$ 反解 index。
  - 直接映像的索引位 $= \log_2(\text{块数})$；组相联的索引位 $= \log_2(\text{组数}) = \log_2\big(\text{容量}/(\text{块大小}\times 相联度)\big)$
- **2:1 经验规则**：容量为 N 的直接映像 Cache 与容量为 N/2 的两路组相联 Cache 不命中率差不多。
- **相联度超过 8 实际意义不大**；且**提高相联度是以增加命中时间为代价的**。

### 5.3 三种不命中（3C）

| 类型 | 成因 | 对策 | 要点 |
| --- | --- | --- | --- |
| **强制性**（冷启动） | 第一次访问某块 | 增大块大小、预取 | **不受相联度和容量影响** |
| **容量** | 程序需要的块不能全部调入 | 增大容量 | 随容量增加而减少；有抖动现象 |
| **冲突** | 太多块映射到同一组 | 提高相联度（理想为全相联） | 相联度越高越少 |

- 块大小与不命中率**非单调**：先降（强制性不命中减少）后升（块数变少、冲突不命中增加）；且增大块会**增大不命中开销**。容量越大，使不命中率最低的块大小越大。
- **牺牲 Cache**（Victim Cache）专治冲突不命中：在 Cache 与下一级之间设全相联的小 Cache，存放被替换出去的块以备重用；对小容量直接映像数据 Cache 效果尤其明显。

### 5.4 写策略（搭配必须记牢）

- **写回法 ↔ 按写分配**；**写直达法 ↔ 不按写分配（绕写法）**
- 写回法：速度快、占用存储器带宽低，但需**修改位**、一致性差
- 写直达法：易于实现、一致性好，但需要**写缓冲器**来减少 **CPU 写停顿**；进一步可用**写缓冲合并**（写缓冲中已有匹配地址且对应位置空闲时把数据合并进去）
- 规定：**写操作必须在确认命中后才进行**

### 5.5 两级 Cache

- $$\text{AMAT} = \text{命中时间}_{L1} + \text{不命中率}_{L1} \times (\text{命中时间}_{L2} + \text{不命中率}_{L2} \times \text{不命中开销}_{L2})$$
- **评价第二级 Cache 要用全局不命中率**（$= \text{不命中率}_{L1} \times \text{不命中率}_{L2}$），**局部不命中率不是好指标**
- L2 容量大 → 实际上几乎没有容量不命中，只剩强制性与冲突不命中
- **L2 不受 CPU 时钟频率约束**（它在关键路径之外），因此设计自由度更大，**适合采用较高相联度**
- 局部不命中率 = 该级不命中次数 / 到达该级的访问次数；全局不命中率 = 该级不命中次数 / CPU 发出的访存总次数

### 5.6 降低命中时间

- 容量小、结构简单（硬件越简单越快）；Cache 访问**流水化**
- **虚拟 Cache**：物理 Cache 的问题是地址转换与访存**串行**；虚拟 Cache 用虚拟地址访问，命中时省去转换，不命中时转换与访存**并行**。但有三个问题，也是它没能全面取代物理 Cache 的原因：
  1. **清空问题** → 标识中增加 **PID 字段**（进程标识符）
  2. **同义与别名** → 反别名法、页着色
  3. **虚拟索引 + 物理标识**（折中方案）→ 容量受页内位移限制：$\text{Cache 容量} \le \text{页大小} \times \text{相联度}$
- **踪迹 Cache**：存放 CPU 执行的**动态指令序列**（含按分支预测展开的指令），提高指令 Cache 的空间利用率；缺点是地址映像机制复杂、同一指令序列可能被重复存放

### 5.7 并行主存系统

| | 关键式 | 说明 |
| --- | --- | --- |
| **单体多字** | 最大带宽 $= \dfrac{mW}{T_M}$ | 实现简单，但**实际带宽远小于最大**：取出的 m 个指令字中若遇分支成功则后面无用、数据不连续、写操作复杂 |
| **多体交叉** | 启动间隔 $t = T_M / m$ | **低位交叉**才解决访问冲突（体号 = 低 $\log_2 m$ 位）；高位交叉体号是高 $\log_2 m$ 位 |

**带宽模型**：$B = \sum_{k=1}^{m} k \cdot P(k)$（每周期能访问到的字数的平均值，**正比于实际带宽**）。指令流中：

$$P(k) = (1-\lambda)^{k-1}\lambda \ (1 \le k < m), \qquad P(m) = (1-\lambda)^{m-1}$$

$\lambda$ 为**转移概率**（给定指令的下条指令地址为非顺序地址的概率）。

**结论**：单纯增大 m 收益有限（转移概率不会很低 + 数据分布离散），标量机一般取 $m \le 8$，向量处理机可取大些。

**体冲突**（两个请求落在同一个体）的对策：软件——循环交换、扩展数组大小使之不是 2 的幂；硬件——**体数取素数**。

### 5.8 虚拟存储器

- 分**页式**（定长，对空间的机械划分）与**段式**（变长，按程序的逻辑意义划分）
- **TLB**：专用的高速缓冲器，存放近期常用**页表项**的副本，同样利用局部性原理。项由标识（虚地址的一部分）和数据（物理页帧号、有效位、保护信息、使用位、修改位）构成。一般比 Cache 的标识存储器更小更快，以免延长 Cache 命中时间
- 多级分层页表使页表大小合适，级数取决于虚拟地址空间大小

**与 Cache 的关键区别**（"主存－辅存"层次）：目的是补**容量**不足（Cache 是补速度）、由**软件**管理（Cache 由硬件）、CPU 对第二级**必须通过第一级**访问（Cache 可直接访问）、典型块/页大小几百到几千字节（Cache 几十字节）、不命中时**切换进程**（Cache 不切换）。

## 6. 输入输出系统

### 6.1 I/O 与整机性能

$$\text{系统响应时间} = \text{I/O 系统的响应时间} + \text{CPU 的处理时间}$$

只提高 CPU 性能没用（Amdahl 的 I/O 版）：例 6.1 中 I/O 占响应时间 10%，CPU 快 10 倍整机只快约 **5 倍**，快 100 倍整机只快约 **10 倍**——**性能被浪费在没有改进的部分上**。

**常见误区**：多进程技术只提高系统**吞吐率**，**不能减少响应时间**。

### 6.2 可靠性三兄弟

- **MTTF**（平均无故障时间）衡量**可靠性**；失效率 $\lambda = 1/\text{MTTF}$
- 生存期服从指数分布时，**系统失效率 = 各部件失效率之和**：
  $$\lambda_{系统} = \sum_i \frac{1}{\text{MTTF}_i}, \qquad \text{MTTF}_{系统} = \frac{1}{\lambda_{系统}}$$
  例 6.2：10 个磁盘 + 控制器 + 电源 + 风扇 + 连线 → $\lambda = 23\times10^{-6}$/h → MTTF ≈ **43478 小时 ≈ 将近 5 年**
  > 推论：**部件越多、系统越不可靠**——这正是 RAID 必须引入冗余的根本原因。
- **MTBF = MTTF + MTTR**（平均失效间隔时间 = 无故障时间 + 修复时间）
- **可用性** $= \dfrac{\text{MTTF}}{\text{MTTF}+\text{MTTR}} = \dfrac{\text{MTTF}}{\text{MTBF}}$
- **可信性**：服务的质量，在多大程度上可以合理地认为服务可靠——**不可度量**

提高可靠性的两类方法：**有效构建法**（构建时消除故障隐患）与**纠错法**（容错）。

### 6.3 RAID

**本质**：用多磁盘**条带化**换并行 I/O 性能，用**冗余信息**换可靠性（N 个磁盘的阵列可靠性降为单盘的 1/N，必须用冗余补回来）。
两个区分特征：**数据交叉存放的粒度**（细/粗）与**冗余的计算与分布方式**。

主线记忆：

- **RAID 0** 无冗余，严格地说**不属于 RAID 系列**
- **RAID 1** 镜像，空间开销×2（最贵），数据恢复简单、读快、写比更高级别快
- **RAID 2** 汉明 ECC，冗余盘数按 $\log_2 m$ 级增长，**没有商业化产品**
- **RAID 3 / 4 / 5 都只需要 1 个校验盘**，区别在交叉粒度：**位交叉** / **块交叉** / **块交叉且奇偶校验分布存放**
- **RAID 6** = P+Q 双校验，**容忍 2 个故障**，校验空间开销是 RAID 5 的两倍
- **RAID 10 = 1+0**（先镜像后条带），**RAID 01 = 0+1**（先条带后镜像）
- 冗余信息**均匀分布到所有盘**以避免**热点问题**——这是 RAID 5 相对 RAID 4 的关键改进（RAID 4 的校验盘是小规模写的瓶颈）

小规模写操作的代价：RAID 4 写数据需 **2 次读 + 2 次写**；**RAID 5 小规模写要访问磁盘 4 次；RAID 6 要 6 次**。

### 6.4 总线

- 优点：成本低、多样性；**根本缺点：由外设分时共享，形成信息交换的瓶颈**，限制系统总的 I/O 吞吐量
- **分离事务总线**（流水总线 / 包交换总线）：把事务分成**请求**与**应答**两部分，中间空闲时间总线可让给其他 I/O 使用 → **带宽更高，但数据传送延迟通常比独占总线更大**
- **同步总线**：有供所有设备使用的统一时钟，快、便宜，但所有操作必须以同样的时钟频率进行；**异步总线**：无统一时钟，各设备有自己的定时方法，采用**握手协议**，更灵活
- I/O 总线可连到**存储器**（更常见）或 Cache
- CPU 对 I/O 设备编址两种方式：**存储器映射 I/O（统一编址）**——用 load/store 即可访问；**独立编址**——需要专用 I/O 指令，且 CPU 要发出标志信号表示访问的是 I/O 地址

### 6.5 四种 I/O 控制方式（演进逻辑：CPU 参与度递减）

**程序查询 → 中断 → DMA → 通道**

| 方式 | 数据传送方向 | 传送单位 | CPU 参与程度 |
| --- | --- | --- | --- |
| 程序查询 | CPU ↔ 外设 | 字/字节 | 全程忙等 |
| 中断 | CPU ↔ 外设 | 字/字节 | 每次传送都要介入 |
| **DMA** | **外设 ↔ 主存（不经 CPU）** | 数据块 | 仅开始/结束介入一次 |
| **通道** | 外设 ↔ 主存（经通道） | 一组数据块 | 只启动通道、结束收中断 |

**DMA 用物理地址的两个问题**：跨页缓冲区的页在物理上不连续；传输中操作系统移动/重定位页面会导致错误写入。解决办法：把页面**"钉"在主存中**（pinned），或采用**虚拟 DMA**（允许 DMA 用虚拟地址、硬件转换，并在进程移动时及时修改 DMA 地址表）。

### 6.6 通道处理机

**通道** = 专门负责整个系统输入/输出工作的处理机，**只能执行有限的一组 I/O 指令**。构成 **CPU — 通道 — 设备控制器 — 外设** 的四级层次结构。

**工作过程三步**：用户程序用**访管指令**进入管理程序 → 管理程序编制通道程序并启动通道（**启动 I/O 指令是特权指令**）→ 通道执行通道程序（**与 CPU 并行**）→ 结束向 CPU 发中断。

| 通道类型 | 服务对象 | 服务方式 | 总时间 T | 最大流量 $f_{max}$ | 实际流量 |
| --- | --- | --- | --- | --- | --- |
| **字节多路** | 多台低速/中速 | 以**字节交叉**方式分时轮流 | $p\,n\,(T_S+T_D)$ | $\dfrac{1}{T_S+T_D}$ | $\sum f_i$ |
| **选择** | 多台高速 | 一台**独占**，传完才切换 | $p\,(T_S+n\,T_D)$ | $\dfrac{n}{T_S+n\,T_D}$ | $\max\{f_i\}$ |
| **数组多路** | 高速 | 每次传送**一个数据块** k 字节后切换 | $\dfrac{p\,n}{k}(T_S+k\,T_D)$ | $\dfrac{k}{T_S+k\,T_D}$ | $\max\{f_i\}$ |

- **记忆锚点**：三个 $f_{max}$ 的分子分别是 **1 / n / k**；只有**字节多路**的实际流量是**累加**，另两种取**最大者**。
- **约束** $f_{实际} \le f_{max}$：两边越接近，通道利用率越高；相等即为**满负荷工作状态**。
- 数组多路能为多台高速设备并行服务，是因为所连设备虽然传输率很高，但**寻址等辅助操作时间很长**。
- 参数：$T_S$ 设备选择时间、$T_D$ 传送一个字节的时间、$k$ 数据块字节数（磁盘磁带通常 $k=512$，一般 $k<n$）。

### 6.7 Cache 与 I/O 的数据一致性

Cache 使数据存在**两个副本**（Cache 与主存），I/O 设备又能修改存储器内容，于是：

- **写直达法不会出现"I/O 输出读到旧值"的问题，写回法才会**
- 输入操作后存储器内容变了，但 CPU 在 Cache 中看到的仍是旧值

两条解决路：

- **软件**：把 I/O 缓冲页设为**不可进入 Cache**；或在输入前把 Cache 中相关数据块置为**"无效"**赶出 Cache
- **硬件**：输入时检查 I/O 地址是否在 Cache 中有副本，命中则把相应 Cache 块置**"无效"**
- 另一种思路是把 **I/O 直接连到 Cache**：天然一致，且所有设备都能看到最新数据；缺点是 I/O 与 CPU **竞争访问 Cache**造成 CPU 停顿，且 I/O 可能把近期用不到的新数据挤进 Cache

## 8. 高频陷阱

1. **相关 ≠ 冲突**。相关是程序固有属性（数据相关还有传递性），冲突是流水线属性；同一次相关是否引发冲突、停顿多久，取决于具体流水线。
2. **WAR/WAW 只在乱序执行时才出现**，经典 5 段流水线不会发生。Tomasulo 用换名消除的是这两个；**RAW 仍然是靠"等"**。
3. **load 的结果无法用定向解决**，必须插暂停（load 互锁）；普通 ALU 相关才可用定向。
4. **保留站里 V 与 Q 只有一个有效，Q=0 表示就绪**；`Qj/Vj` 对应第一个源操作数 `rs`，`Qk/Vk` 对应 `rt`；load 的 `Vk` 放的是偏移量。
5. **BHT 对 5 段经典流水线无收益**（判定分支成功与计算目标地址都在 ID 段完成）；它只在"判定成功比算目标更慢"时才有用。
6. **$E = TP \cdot \Delta t$ 只适用于各段等时**；各段不等时用 $E = S/k$ 或面积法。
7. **$TP \approx TP_{max}$、$S \approx k$ 需要 $n \gg k$**，不能随意取等号。
8. **静态流水线功能切换必须等前一种运算全部流出（排空）**，这是它效率低于动态流水线的主因；而动态流水线的代价是控制复杂。
9. **平均访存时间低 ≠ CPU 时间低**（例 5.2：提高相联度使 AMAT 下降，但时钟周期变长，CPU 时间反而升高）。**最终一律看 CPU 时间。**
10. **不命中开销 $T_M = T_2 + T_B$，不含命中的 $T_1$**；而"不命中时的访问时间" = $T_1 + T_M$。另外命中率的分母是访问 M1 与 M2 的次数之和。
11. **两级 Cache 的公式里 L2 用的是局部不命中率，但评价 L2 该用全局不命中率。** 另注意全局不命中率 = L1 不命中率 × L2 不命中率。
12. **写回 ↔ 按写分配、写直达 ↔ 不按写分配**，不要配错；且只有写回法才会有"输出操作读到 Cache 旧值"的一致性问题。
13. **系统失效率是各部件失效率"相加"而不是"取最大"**，且同类部件的数量要乘上去（10 个磁盘是 $10\times$）。
14. **三个通道 $f_{max}$ 的分子是 1 / n / k**；只有字节多路的实际流量是**累加**，选择与数组多路取**最大者**。
15. **分离事务总线带宽更高，但延迟更大**（不是更小）。
16. **多进程提高吞吐率，不减少响应时间。**
17. **MIPS 的位编号从最高位为第 0 位开始**（与常识相反）；`##` 是拼接、上标是复制次数、下标是位/位范围。
