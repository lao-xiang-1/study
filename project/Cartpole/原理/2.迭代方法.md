#review 

>基于GridWorld讲解

迭代方法（值迭代、策略迭代、截断策略迭代）解决的是同一个问题：**已知环境的完整模型（转移概率 $P$ 与奖励 $R$），如何求出最优价值函数 $V^*$ 与最优策略 $\pi^*$**。它们都属于**动态规划（Dynamic Programming）**——用贝尔曼方程把"求全局最优"拆成"反复做局部备份"。

三者的差别只在一处：**策略评估要做多久**。

## 引子：一个 4×4 的网格世界

### 环境设定

| 要素 | 取值 |
| :--- | :--- |
| 状态 $s$ | 16 个格子（$4\times4$） |
| 动作 $a$ | 上 / 下 / 左 / 右（4 个） |
| 转移 $P(s'\mid s,a)$ | **确定性**：执行动作必到相邻格；撞墙则停在原地 |
| 奖励 $R(s,a)$ | 每走一步 $-1$；到达终点后终止（$V(\text{终点})=0$） |
| 折扣因子 $\gamma$ | $0.9$ |
| 目标 | 从任意格子出发，以**最少步数**走到右下角终点 |

因为转移是确定性的，$P(s'\mid s,a)$ 只取 0 或 1，所以下面式子里的 $\sum_{s'}P(s'\mid s,a)V(s')$ 实际就是**取某个邻居的 $V$**，写起来直观。

### 两条贝尔曼方程

**贝尔曼期望方程**——固定策略 $\pi$，描述"按 $\pi$ 走"能拿多少：

$$V^\pi(s)=\sum_{a\in\mathcal{A}}\pi(a\mid s)\Big[R(s,a)+\gamma\sum_{s'\in\mathcal{S}}P(s'\mid s,a)\,V^\pi(s')\Big]$$

**贝尔曼最优方程**——不指定策略，直接把 $\max$ 写进去：

$$V^*(s)=\max_{a\in\mathcal{A}}\Big[R(s,a)+\gamma\sum_{s'\in\mathcal{S}}P(s'\mid s,a)\,V^*(s')\Big]$$

两者可以看作两个算子的不动点方程：

- **贝尔曼期望算子** $T^\pi$：$T^\pi V(s)=\sum_a\pi(a\mid s)\big[R+\gamma\sum_{s'}P\,V(s')\big]$，不动点是 $V^\pi$。
- **贝尔曼最优算子** $T^*$：$T^*V(s)=\max_a\big[R+\gamma\sum_{s'}P\,V(s')\big]$，不动点是 $V^*$。

> **为什么迭代一定收敛**：当 $\gamma<1$ 时，$T^\pi$ 与 $T^*$ 都是 **$\gamma$-压缩映射（contraction mapping）**，即对任意 $V_1,V_2$ 有 $\|T V_1-TV_2\|_\infty\le\gamma\|V_1-V_2\|_\infty$。由 Banach 不动点定理，反复作用必收敛到**唯一**不动点。这正是下面所有迭代算法的理论依据。

## 值迭代
>**思路**：初始状态值设置为0，遍历所有状态和动作，取出最优值，继续迭代直到收敛。

**状态更新公式**：
$$V_{k+1}(s)=\max_{a\in\mathcal{A}}\Big[R(s,a)+\gamma\sum_{s'\in\mathcal{S}}P(s'\mid s,a)\,V_k(s')\Big],\qquad V_0(s)=0$$

**策略提取**：值迭代本身可以不产生策略，收敛后用贪心一步把它"读"出来：
$$\pi^*(s)=\arg\max_{a\in\mathcal{A}}\Big[R(s,a)+\gamma\sum_{s'}P(s'\mid s,a)\,V^*(s')\Big]$$

**伪代码**：

> 下文 `P(s_next, s, a)` 即 $P(s'\mid s,a)$；`argmax_a` 表示对动作取最大。

```python
# 值迭代（Value Iteration）：直接对贝尔曼最优算子做备份
V = {s: 0.0 for s in states}                 # V_0(s) = 0
while True:
    delta = 0.0
    for s in states:
        v_old = V[s]
        # 在该状态下，对每种动作求回报，取最大值更新状态值
        V[s] = max(R(s, a) + gamma * sum(P(s_next, s, a) * V[s_next]
                                         for s_next in states)
                   for a in actions)
        delta = max(delta, abs(V[s] - v_old))
    if delta < theta:                        # 整轮最大变化量小于阈值 → 收敛
        break

# 策略提取：迭代过程中可以不算策略（反正要遍历所有动作），而在收敛之后一次性算出来
pi = {}
for s in states:
	# 取一个固定动作，使当前状态的回报值最大
    pi[s] = argmax_a(R(s, a) + gamma * sum(P(s_next, s, a) * V[s_next]
                                           for s_next in states))
```

## 策略迭代

**思路**：把"评估"与"改进"拆成两个显式的交替步骤，评估**跑到收敛**再改进。

**① 策略评估（Policy Evaluation）**：固定当前策略 $\pi$，把贝尔曼期望方程迭代到收敛，得到 $V^\pi$：

$$V(s)\leftarrow \sum_{a}\pi(a\mid s)Q(a,s)= \sum_{a}\pi(a\mid s)\Big[R(s,a)+\gamma\sum_{s'}P(s'\mid s,a)V(s')\Big]\quad\text{直到收敛}$$

**② 策略改进（Policy Improvement）**：用刚算出的 $V^\pi$ 做一步贪心，得到更好的策略：

$$\pi'(s)=\arg\max_{a\in\mathcal{A}}\Big[R(s,a)+\gamma\sum_{s'}P(s'\mid s,a)V^\pi(s')\Big]$$

**终止条件**：若 $\pi'=\pi$（策略不再变化），则 $V^\pi=V^*$，$\pi$ 已是最优。

**伪代码**：

```python
# 策略迭代（Policy Iteration）：评估跑到收敛，再改进
pi = random_policy(states)                   # 初始策略（如均匀随机）
V = {s: 0.0 for s in states}                 # 价值函数跨轮沿用，不重置
while True:
    # ① 策略评估：固定 pi，把贝尔曼期望方程迭代到收敛
    while True:
        delta = 0.0
        for s in states:
            v_old = V[s]
            V[s] = sum(pi[s][a] * (R(s, a) + gamma * sum(
                       P(s_next, s, a) * V[s_next] for s_next in states))
                       for a in actions)
            delta = max(delta, abs(V[s] - v_old))
        if delta < theta:                    # 评估已收敛
            break
    # ② 策略改进：对 V 做一步贪心，同时检查策略是否稳定
    stable = True
    for s in states:
        greedy = argmax_a(R(s, a) + gamma * sum(
                          P(s_next, s, a) * V[s_next] for s_next in states))
        if pi[s] != greedy:                  # 有状态的最优动作变了
            stable = False
            pi[s] = greedy
    if stable:                               # pi' == pi → 已最优
        break
```

**收敛保证**——**策略改进定理**：贪心得到的新策略一定不劣于旧策略，$V^{\pi'}\ge V^\pi$（逐状态成立），且只要 $\pi'$ 与 $\pi$ 不同就严格更优。有限 MDP 的策略数有限，故**有限步内必然收敛**。

从均匀随机策略出发，本例的迭代轨迹：

| 轮次 | 本轮评估扫描次数 | 策略改变的状态数 | $V(0,0)$ |
| :--- | :--- | :--- | :--- |
| 1（评估初始随机策略） | 242 | — | -9.36 |
| 2 | 7 | 4 | -4.69 |
| 3 | 1 | 0（收敛） | -4.69 |

**要点**：

- **外层轮数很少，但每轮很贵**。第一轮为了把随机策略评估到收敛，扫描了 **242** 次；此后每轮只有个位数。这正是策略迭代的特征——用昂贵的评估换极少的改进轮数。
- 评估也可以**精确求解**：把期望方程写成线性方程组 $V=R^\pi+\gamma P^\pi V$，直接解 $V=(I-\gamma P^\pi)^{-1}R^\pi$。状态少时可行，状态多时仍只能迭代。
- 策略迭代与值迭代的**改进步完全相同**，差别只在评估是否跑到收敛。

## 截断策略迭代

**思路**：既然策略评估跑到收敛很贵，那就不跑完——**每轮只评估 $k$ 次就去做改进**：

$$\text{评估 }k\text{ 次}\;\longrightarrow\;\text{改进}\;\longrightarrow\;\text{评估 }k\text{ 次}\;\longrightarrow\;\text{改进}\;\longrightarrow\cdots$$

**伪代码**：

```python
# 截断策略迭代（Truncated Policy Iteration）：每轮只评估 k 次就改进
pi = random_policy(states)
V = {s: 0.0 for s in states}
while True:
    # 评估 k 次（k = 1 → 值迭代；k → ∞ → 策略迭代）
    for _ in range(k):
        for s in states:
            V[s] = sum(pi[s][a] * (R(s, a) + gamma * sum(
                       P(s_next, s, a) * V[s_next] for s_next in states))
                       for a in actions)
    # 改进一次
    stable = True
    for s in states:
        greedy = argmax_a(R(s, a) + gamma * sum(
                          P(s_next, s, a) * V[s_next] for s_next in states))
        if pi[s] != greedy:
            stable = False
            pi[s] = greedy
    if stable:
        break
```

这一族方法就是**截断策略迭代（Truncated Policy Iteration）**，它把前两者统一为两个极端：

- $k\to\infty$（评估到收敛）$\;\Rightarrow\;$ **策略迭代**
- $k=1$（只评估一次）$\;\Rightarrow\;$ **值迭代**

**为什么 $k=1$ 就是值迭代**：只评估一次时，评估步为 $\tilde V(s)\leftarrow R(s,\pi(s))+\gamma\tilde V(s')$，改进步随即用 $\tilde V$ 做贪心。把两步合并（改进直接作用在刚评估出的值上），就得到

$$V(s)\leftarrow\max_a\Big[R(s,a)+\gamma V(s')\Big]$$

正是值迭代的最优算子备份。**所以值迭代 = 截断到 1 次的策略迭代。**

### 广义策略迭代（GPI）

把"评估"与"改进"看作两股互相拉扯的力量：

- **评估**让价值函数 $V$ 去追当前策略 $\pi$（$V\to V^\pi$）；
- **改进**让策略 $\pi$ 去追当前价值函数 $V$（$\pi\to$ greedy$(V)$）。

两者反复交替，最终在 $V^*$、$\pi^*$ 处**同时稳定**——此时 $V$ 与 $\pi$ 彼此不再改变。任何"评估—改进"的交替方式都叫**广义策略迭代（Generalized Policy Iteration, GPI）**，值迭代与策略迭代都是它的特例。

### 评估次数 $k$ 的取舍

| $k$ | 每轮评估成本 | 外层轮数 | 定位 |
| :--- | :--- | :--- | :--- |
| $1$ | 最低 | 最多 | 值迭代 |
| 中等 | 折中 | 折中 | 截断策略迭代 |
| $\to\infty$ | 最高 | 最少 | 策略迭代 |

$k$ 是"**每轮算多细**"与"**要跑多少轮**"之间的旋钮：算得越粗，单轮越便宜，但需要更多轮才能把信息传遍整个状态空间；算得越细，单轮越贵，但轮数越少。

> **与 PPO 的联系**：在 CartPole/PPO 这类**函数逼近 + 采样**的场景里，状态空间无法枚举，"扫描"变成了"在同一批数据上做若干次梯度更新"。PPO 的 `n_epochs = 10`（见 [PPO 优化算法](PPO%20优化算法.md)）正是这个 $k$ 的类比——用旧数据反复更新，但用 clip 把单次更新幅度限制住。区别在于：动态规划里 $k$ 越大越好（评估更准），而 PPO 里 $k$ 太大反而会让新策略偏离旧数据、把重要性采样比值 $r_t$ 拉爆（见 [信任域约束与 PPO-Clip](信任域约束与%20PPO-Clip.md)）。
