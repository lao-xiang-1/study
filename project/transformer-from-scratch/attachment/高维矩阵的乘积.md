# 附：高维矩阵的 `@` 运算（批量矩阵乘）

> 相关代码：`attention.py` 中的 `scaled_dot_product_attention` / `MultiheadAttention`
> 验证脚本：`temp/check_batched_matmul.py`
> 一句话：`@` 作用在 >2 维张量时，**只有最后两维参与矩阵乘法，前面所有维都是 batch 维**。

---

## 1. 核心规则

```
[..., m, k] @ [..., k, n]  ->  [..., m, n]
```

- 前面的维度都看作batch维，维度必须匹配（可广播，下面是[具体规则](#2.%20batch%20维的广播规则)）
- 最后两维矩阵相乘，符合二维矩阵计算规则

---

## 2. batch 维的广播规则

batch 维遵守普通广播规则：**右对齐、size-1 维可扩展、缺的维补 1**。

| 左操作数 | 右操作数 | 结果 |
|---|---|---|
| `(2, 3, 5, 4)` | `(2, 3, 4, 6)` | `(2, 3, 5, 6)` |
| `(7, 5, 4)` | `(7, 4, 6)` | `(7, 5, 6)` |
| `(2, 3, 5, 4)` | `(4, 6)` | `(2, 3, 5, 6)` |
| `(2, 3, 5, 4)` | `(1, 1, 4, 6)` | `(2, 3, 5, 6)` |
| `(2, 3, 5, 4)` | `(3, 4, 6)` | `(2, 3, 5, 6)` |
| `(2, 3, 5, 4)` | `(7, 4, 6)` | ❌ batch 维不兼容 |
| `(2, 3, 5, 4)` | `(2, 3, 5, 6)` | ❌ inner dim 不匹配 |

---

## 3. 语义：一堆独立的小矩阵乘

```
(2, 3, 5, 4) @ (2, 3, 4, 6)
└─┬─┘
  6 个独立的 (5,4) @ (4,6)
```

`2 × 3` 个矩阵各算各的，互不影响。

---

## 4. 在 attention 里的实际调用

```
q @ k^T  (2, 4, 7, 8) @ (2, 4, 8, 7) -> (2, 4, 7, 7)
attn @ v (2, 4, 7, 7) @ (2, 4, 7, 8) -> (2, 4, 7, 8)
```

`B=2, H=4` 是 batch 维 → **8 个独立的 7×7 注意力矩阵，每个 `(batch, head)` 组合一个**。

**这就是多头能「并行」的全部机制** —— 不是写了循环，而是把 head 塞进了 batch 维。

第二行里 `7`（`S_k`）被消掉，正好对应「加权求和」：沿着 key 那一维求和。

---

## 5. 坑：`.T` 不能用

```
q.T                   -> (8, 7, 4, 2)     # ❌ 反了所有维！
                         UserWarning: deprecated, 未来版本直接报错
q.transpose(-2, -1)   -> (2, 4, 8, 7)     # ✅ 只交换最后两维
q.permute(0, 1, 3, 2) -> (2, 4, 8, 7)     # ✅ 等价写法
```

`q.T` 在 >2 维时会把**所有**维度倒过来（`(2,4,7,8) → (8,7,4,2)`），语义完全错了，而且现在已 deprecated，未来直接抛错。

所以代码里写的是 `k.transpose(-2, -1)` —— 只有它才能表达「把矩阵转置，别动 batch 维」。

> PyTorch 提示里提到的 `x.mT` 是专门的「批量转置」，同样只交换最后两维。

---

## 6. 一个浮点细节

批量 matmul 和「循环做 2D matmul」**数学上等价，但不逐位相同**：

```
batched vs loop: bit-identical = False, max abs diff = 4.768e-07
```

原因是批量 GEMM 的累加顺序和逐个算不同。量级是 float32 的 ULP 级别，实践上无所谓。

> 同样的现象也出现在 `qkv_proj` 融合投影上：一个 `Linear(input, 3*emb)` 和三个独立 `Linear(input, emb)` 数学等价，但数值上不保证逐位相同。
>
> **结论：别用 `torch.equal` 去比对「融合写法 vs 拆分写法」，要用 `torch.allclose`。**
