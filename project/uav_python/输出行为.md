原因是**检测到的线切片数 `cnt` 从 2 掉到了 1**，触发了代码里的分支跳转。
>并不是表示检测到红点

看 [main.py:708](vscode-webview://1lb5v7n0aq23eehou6tfrjcpgdlkk5re6q7q3ijv1jl81mo33m1i/main.py#L708) 这条 `Count: {cnt}` 是每帧无条件打印的，它就是切片里检测到线的数量。你的日志里它从 `Count: 2` 变成 `Count: 1`。

关键在 [main.py:727](vscode-webview://1lb5v7n0aq23eehou6tfrjcpgdlkk5re6q7q3ijv1jl81mo33m1i/main.py#L727)：

```python
if self.is_follow and cnt >= 2:
    speed_row = round(self.pid_r.pid_calculate(...))   # <- pid 日志
    ...
    self.airplaneApi.move(...)
    logger.info(f"row correct ...")                     # <- row correct 日志
```

PID 计算、`move` 指令、`row correct` 这些日志**全部在 `cnt >= 2` 这个条件块里**。一旦 `cnt` 掉到 1，整个块被跳过，于是：

- `pid:pid_calculate` 的 row/yaw 日志 → 消失
- `row correct ...` → 消失
- 只剩 `Count: 1`（708 行，块外）和 `decode:630 qr_cnt=0`（每帧独立运行的二维码解码）继续打印

所以"突然变化"不是异常，而是**线在画面里变细/部分丢失，只剩 1 个切片能检测到中心点**。常见于：快到线末端、线被红点/QR 标记遮挡、或无人机正在偏离线。

要进一步判断，可以看：

- `Count` 后续是否回到 2（线又回来 → 正常丢线一帧）
- 是否一直停在 1 甚至 0（线彻底丢了 → 要看后续是触发盲飞兜底还是别的分支）
- 配合 `--show` 画面的 Result 叠加图看线在那个时刻长什么样
